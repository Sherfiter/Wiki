# 第 5 章 · 网络层：IP 与路由

网络层的使命：**在任意两台主机之间找到一条路径，把分组（packet）从源送到目的**。它只承诺「尽力而为（best-effort）」——不保证到达、不保证顺序，可靠性交给传输层（见第 4 章）。

## 5.1 IPv4 地址

IPv4 地址是 **32 位**，通常写成点分十进制 `192.168.1.1`，分「网络号 + 主机号」两部分。前缀长度决定网络部分多长：

| 表示 | 含义 |
|---|---|
| `192.168.1.0/24` | CIDR 记法：前 24 位是网络号，主机位 8 位，可容纳 2^8−2=254 台主机 |
| 子网掩码 `255.255.255.0` | 等价于 /24 |

特殊地址：全 0 主机位 = 网络地址，全 1 主机位 = 广播地址（这两个不能分配给主机）。

## 5.2 子网划分与 CIDR

**子网划分**：把一个大网络切成若干小网络，方法是**借主机位当网络位**，延长前缀。**CIDR（无类别域间路由）** 取消 A/B/C 类的固定边界，允许任意长度前缀，路由表用 `网络/前缀` 聚合——这是现代互联网的基础。

> 对比（IPv4 vs IPv6）：**IPv4 地址 32 位、约 43 亿个，早已耗尽**，靠 NAT 续命；**IPv6 地址 128 位**，空间大到可忽略耗尽问题，地址写法 `2001:db8::1`（双冒号压缩连续的 0），并原生支持无状态自动配置（SLAAC，见第 2 章 DHCP 对比）。IPv6 去掉了首部校验和，把分片从路由器移到端点，简化了转发。

## 5.3 路由算法：距离向量 vs 链路状态

路由器靠**路由算法**计算转发表。两大类：

> 对比：**距离向量（如 RIP）** 是「只跟邻居交换，听别人怎么走」——每个路由器把「到各网络的距离表」告诉邻居，迭代收敛；**链路状态（如 OSPF）** 是「把全网拓扑广播给所有人，各自算」——每个路由器掌握完整拓扑，用 Dijkstra 求最短路径。

| 维度 | 距离向量（RIP） | 链路状态（OSPF） |
|---|---|---|
| 信息 | 到各网络的距离（跳数） | 全网链路状态 |
| 交换对象 | 只与邻居 | 泛洪全网 |
| 算法 | Bellman-Ford | Dijkstra |
| 收敛速度 | 慢（坏消息传得慢） | 快 |
| 度量 | 跳数（≤15 跳） | 可自定义（带宽、代价） |
| 适用规模 | 小型网络 | 大型自治系统内部 |

距离向量的问题：**「坏消息传得慢」**——链路断开后，路由环路/计数到无穷可能持续很久（RIP 用 16 跳表示不可达来兜底）。

## 5.4 ICMP：网络层的「诊断员」

**ICMP** 是 IP 的辅助协议，用于报告错误和诊断，不发应用数据：

- `ping`：发送 **ICMP Echo Request**，对端回 **Echo Reply**，测连通性与 RTT。
- `traceroute`：发送 TTL 递增的包，收集沿途路由器返回的 **TTL 超时** 消息，画出路径。
- 典型错误：目的不可达、超时、重定向。

## 5.5 NAT：地址转换

**NAT（网络地址转换）** 让多台私有地址主机共享一个公网 IP 上网：

```
内网 192.168.1.x  ──→  NAT 路由器  ──→  公网 IP（如 203.0.113.5）
```

- 路由器维护一张**转换表**（内网 `IP:端口` ↔ 公网 `IP:端口`），把内网地址替换成公网地址再发出去，回程再换回来。
- 一举两得：**缓解 IPv4 耗尽** + **隐藏内网拓扑（天然防火墙）**。
- 代价：**破坏了端到端原则**——外网无法主动发起连接到内网主机（需端口映射/打洞），也让某些协议（如 FTP、IPsec）更麻烦。

> 承上启下：网络层用 IP 地址做全局寻址、用路由算法找路。但 IP 分组最终要落到**某一段物理链路**上传输，这就进入第 6 章的链路层——那里用 MAC 地址在同一网段内寻址，靠 ARP 把 IP 映射成 MAC。
