# 第 1 章 · 网络概述与分层

网络如此复杂，是因为它要同时解决传输介质、寻址、路由、可靠性、安全等一系列问题。**分层（layering）** 是把这些难题拆开的唯一办法——每一层只解决自己那一层的问题，向上层提供服务，向下层屏蔽细节。

## 1.1 OSI 七层 vs TCP/IP 四层

OSI 是 ISO 提出的**理想参考模型**（七层），TCP/IP 是现实中实际运行的**协议栈**（四层，教学中也常按五层讲）。二者的对应关系：

| 层 | OSI（7 层） | TCP/IP（4 层） | 常见协议/设备 |
|---|---|---|---|
| 7 | 应用层 | 应用层 | HTTP、DNS、SMTP、DHCP |
| 6 | 表示层 | （并入应用层） | 加密、编码、压缩 |
| 5 | 会话层 | （并入应用层） | 会话建立/管理 |
| 4 | 传输层 | 传输层 | TCP、UDP |
| 3 | 网络层 | 网络层 | IP、ICMP、路由器 |
| 2 | 数据链路层 | 网络接口层 | 以太网、MAC、交换机 |
| 1 | 物理层 | 网络接口层 | 网线、光纤、集线器 |

> 对比：OSI 是「先有模型、后有协议」，层次划分追求完美对称，但 5/6/7 三层在实践中几乎从不被单独实现，因此 TCP/IP 把它们合并成一层。**OSI 胜在概念清晰、适合教学；TCP/IP 胜在简单实用、真实落地。** 现在说「几层」几乎总是指 TCP/IP 的 4 层（或教学上的 5 层：物理层、链路层单列）。

## 1.2 分层思想：服务、接口、协议

每一层都要分清三个概念：

- **服务（service）**：本层向上层提供的能力（「我能做什么」），如传输层提供「可靠的字节流」。
- **接口（interface）**：上下层之间交互的方式（「怎么调用我」），如 socket 就是应用层到传输层的接口（见第 9 章）。
- **协议（protocol）**：**对等层之间**通信的规则（「同一层怎么对话」），如 TCP 规定报文格式与握手流程（见第 4 章）。

**关键区分**：层与层之间是「垂直」的调用关系（服务/接口），对等层之间是「水平」的对话关系（协议）。数据真正在物理介质上流动，但逻辑上，只有**对等层**在「互相理解」——这叫**对等层通信**。

## 1.3 封装与解封装

数据从发送端应用层一路往下，每经过一层就**加上本层的头部**（可能还有尾部），这个过程叫**封装（encapsulation）**；接收端再逐层剥掉，叫**解封装（decapsulation）**。

```
应用层:      [ HTTP 数据 ]
传输层:   [ TCP 首部 | HTTP 数据 ]              ← 段 segment
网络层: [ IP 首部 | TCP 首部 | HTTP 数据 ]       ← 包 packet
链路层: [ 帧头 | IP 首部 | ... | 帧尾 ]          ← 帧 frame
物理层: 0101101001...（比特流）                  ← 比特 bit
```

- 每层的头部只被**对等层**解读：TCP 首部只有对端 TCP 读，IP 首部只有对端 IP 读。
- 上层数据对下层是**不透明的负载（payload）**——路由器只看到 IP 首部，不关心里面是 TCP 还是 UDP。

## 1.4 为什么分层

1. **解耦**：改物理介质（双绞线换光纤）不影响上面的 HTTP；改应用不影响链路层。
2. **简化设计**：每个协议只需解决一个层面的问题，不必从零实现整套网络。
3. **互操作性**：只要遵守同一层协议，不同厂商的设备/软件就能互通。
4. **可测试、可演进**：可以单独替换某一层（如 IPv4 → IPv6，见第 5 章）。

代价是**冗余与性能损耗**——每层都加头，还要在层间拷贝数据；极端性能场景（如内核旁路、RDMA）会想办法「绕过分层」。
