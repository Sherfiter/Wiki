# 第 4 章 · TCP 可靠传输

TCP 承诺「可靠」：数据不丢、不重、不乱序、按需送达。这一章拆解它如何做到——靠**三次握手建立连接、滑动窗口流水线传输、确认与重传、流量与拥塞控制**，最后**四次挥手**优雅断开。

## 4.1 三次握手：为什么是三次

建立连接要双方确认「我能发、我能收、对方能收」，于是走 **SYN → SYN+ACK → ACK** 三步：

```
客户端                      服务器
  │ ──── SYN, seq=x ────→    │   ① 我请求建连
  │ ←─ SYN+ACK, seq=y, ack=x+1 ─│ ② 我同意，并请求反向建连
  │ ──── ACK, seq=x+1, ack=y+1 →│ ③ 我确认收到
  │        连接建立            │
```

**为什么不是两次？** 两次只保证客户端→服务器的方向可靠；服务器并不知道自己的 SYN 是否被客户端收到，也防不住「历史失效 SYN」——若一个迟到的旧 SYN 到达服务器，两次握手会让服务器误以为建立了连接。**第三次 ACK 让服务器确认客户端确实想连，而不是一个早已过期的重传请求。**（为什么不是四次？因为服务器可以把「对客户端的 ACK」和「自己的 SYN」合并在一个报文里发。）

## 4.2 四次挥手与 TIME_WAIT

TCP 连接是**全双工**的，两个方向要分别关闭，所以挥手是四次：

```
客户端                      服务器
  │ ──── FIN ────→           │   ① 我没数据了，关我→你的方向
  │ ←──── ACK ────           │   ② 收到（但你→我的方向还开着）
  │ ←──── FIN ────           │   ③ 我也没数据了，关我→你的方向
  │ ──── ACK ────→           │   ④ 收到，双方关闭
```

- 中间两次可以不对称：服务器收到 FIN 后可能还有数据要发，所以先 ACK、发完再 FIN。
- **TIME_WAIT**：主动关闭方在发出最后的 ACK 后，还要等 **2MSL（最长报文寿命的两倍，约 60s）** 才真正释放。原因：① 确保最后的 ACK 能到达（若丢失对方会重发 FIN，否则对端永远收不到确认）；② 让「旧连接的迟到报文」在网络里彻底消亡，避免污染下一个复用同一端口的新连接。

## 4.3 滑动窗口与流水线传输

若每个报文都要等确认才能发下一个（停等协议），带宽利用率极低。TCP 用**滑动窗口**允许连续发送多个报文而无需逐个确认：

- **发送窗口** = 已发送未确认 + 可立即发送的字节范围；**接收窗口** = 接收方能缓存的字节范围。
- **确认号 ack = 期望收到的下一个字节序号**，是**累计确认**——收到 ack=n 表示 n 之前的字节全部到达。
- 发送方收到 ACK 后窗口**右滑**，腾出空间继续发；用**序号**保证有序，用**超时重传**处理丢包。

## 4.4 流量控制 vs 拥塞控制

两者都限制发送速率，但针对的问题完全不同：

> 对比：**流量控制是「端到端」的，防止快发送方撑爆慢接收方；拥塞控制是「全网」的，防止太多数据同时涌入网络导致拥塞。**

| 维度 | 流量控制 | 拥塞控制 |
|---|---|---|
| 针对对象 | 接收方处理能力 | 网络整体承载能力 |
| 依据 | 接收窗口 rwnd（对方首部窗口字段） | 网络拥塞信号（丢包/时延） |
| 作用范围 | 一对主机之间 | 全网，全局问题 |
| 实现 | 滑动窗口按 rwnd 收缩 | 拥塞窗口 cwnd 动态调整 |

实际发送窗口 = **min(rwnd, cwnd)**——既不能超过接收方，也不能超过网络。

## 4.5 拥塞控制：四种算法

拥塞窗口 **cwnd** 的变化分四个阶段，由丢包信号（3 个重复 ACK 或超时）触发切换：

| 算法 | cwnd 变化 | 何时退出 |
|---|---|---|
| 慢启动 | 每收到一个 ACK，cwnd +1 MSS（每 RTT 翻倍） | 到达慢启动阈值 ssthresh 或丢包 |
| 拥塞避免 | 每 RTT 线性 +1（加性增） | 发生丢包 |
| 快重传 | 收到 3 个重复 ACK 立即重传，不等超时 | 触发快恢复 |
| 快恢复 | ssthresh=cwnd/2，cwnd=ssthresh，进入拥塞避免 | 重传成功 |

- **慢启动其实不慢**——指数增长，很快；「慢」是相对「一开始就全速」而言。
- 丢包后的处理：**超时**（严重）→ cwnd 归 1，重新慢启动；**3 个重复 ACK**（轻微）→ cwnd 减半，进入快恢复（**TCP Reno**）。
- 组合起来就是经典的 **AIMD（加性增、乘性减）**：正常时缓慢加、拥塞时果断砍半。

> 对比：**慢启动 + 拥塞避免**是「探测网络容量」的经典组合，指数探测 + 线性逼近；**快重传 + 快恢复**是后来的优化，用「3 个重复 ACK」快速定位丢包，避免每次丢包都退回慢启动、吞吐量骤降。前者管「怎么增长」，后者管「丢包了怎么优雅降级」。

> 承上启下：这一章解释了第 3 章 TCP 首部里序号、确认号、窗口字段的用途。可靠传输建立在网络层「尽力而为」的 IP 之上（见第 5 章），而 socket 编程里 `connect`/`close` 背后就是握手与挥手（见第 9 章）。
