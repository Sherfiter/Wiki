# 第 10 章 · 一次请求的完整旅程

前面 9 章分层拆解了网络的每一块。这一章反过来——**追踪一次真实请求，看它在各层之间如何接力**。当你在浏览器地址栏敲下 `https://example.com/page` 并回车，会发生下面这一长串事。

## 10.1 全链路：从 URL 到页面

```
1. DNS 解析        把 example.com 变成 IP        —— 第 2 章
2. TCP 三次握手    与服务器 443 端口建连          —— 第 3、4 章
3. TLS 握手        协商会话密钥，验证证书         —— 第 8 章
4. HTTP 请求       发出 GET /page               —— 第 2 章
5. 服务器处理      生成响应                      —— 第 2 章
6. HTTP 响应       状态码 + 正文返回             —— 第 2 章
7. 四次挥手        连接优雅关闭                  —— 第 4 章
8. 浏览器渲染      解析 HTML/CSS/JS 画页面        —— 浏览器层
```

而贯穿 2–6 步的每一次数据下发，都要再经过 **TCP 分段 → IP 分组 → 以太网帧 → 物理信号** 的逐层封装，中间跨越多台路由器、交换机（见第 5、6、7 章）。

## 10.2 逐层拆解

**① DNS 解析（第 2 章）**：浏览器查缓存 → 本地 DNS 服务器递归查询 → 根/顶级域/权威服务器迭代查询，拿到 `example.com` 的 IP。若之前访问过，可能直接命中缓存，跳过整段。

**② 建立 TCP 连接（第 3、4 章）**：浏览器用随机端口（如 52000）向服务器 443 端口发起 SYN，三次握手后连接建立——`connect` 在这里完成（第 9 章）。

**③ TLS 握手（第 8 章）**：ClientHello → 服务器证书 → 验证证书 → 协商出会话密钥。此后所有 HTTP 数据都用对称加密传输。

**④ 发送 HTTP 请求（第 2 章）**：

```http
GET /page HTTP/1.1
Host: example.com
Accept: text/html
```

**⑤ 服务器处理与响应（第 2 章）**：服务器返回 `200 OK` + HTML 正文。

**⑥ 可靠传输（第 4 章）**：响应被 TCP 分段、编号，靠滑动窗口流水线发送，途中若丢包靠快重传恢复——这些对应用层完全透明。

**⑦ 路由转发（第 5 章）**：每个 IP 分组沿途经过多台路由器，每台查路由表选下一跳；跨网段时靠 ARP（第 6 章）把下一跳 IP 映射成 MAC。

**⑧ 物理传输（第 7 章）**：比特被编码（如 4B/5B、曼彻斯特）成信号，走双绞线/光纤，最终到达服务器或客户端。

**⑨ 断开连接（第 4 章）**：HTTP/1.1 持久连接可复用，多个请求共用一条 TCP；空闲后四次挥手关闭，主动方进入 TIME_WAIT。

## 10.3 用 curl 观察

```bash
curl -v https://example.com/page      # 打印 DNS、握手、请求全过程
```

`-v` 会依次显示：`Trying <IP>...`（DNS 结果）、连接建立、TLS 握手（`SSL connection using TLSv1.3`）、请求头、响应头。用 `tcpdump -i any port 443` 抓包，能直接看到 SYN/FIN、TLS ClientHello、HTTP 报文。

## 10.4 各层知识点对照表

> 对比：一次请求把 2–8 章的知识全部串起来，每一层在真实请求里各司其职：

| 层 | 章节 | 在这次请求中做了什么 |
|---|---|---|
| 应用层 | 第 2 章 | DNS 解析、HTTP 请求/响应 |
| 安全层 | 第 8 章 | TLS 握手、证书验证、加密 |
| 传输层 | 第 3、4 章 | 端口寻址、三次握手、可靠传输、拥塞控制 |
| 网络层 | 第 5 章 | IP 寻址、路由转发、ICMP 诊断 |
| 链路层 | 第 6 章 | MAC 寻址、ARP、帧封装 |
| 物理层 | 第 7 章 | 信号编码、介质传输 |

> 承上启下：这一章是整门课的**闭环**——第 1 章提出的分层模型在这里被重新拼成完整的图景，第 2～8 章的每个知识点都在一次请求里找到了自己的位置。至此，从「敲下回车」到「页面渲染」，中间每一层发生了什么，你都有了答案。
