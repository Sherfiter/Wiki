# 第 2 章 · 应用层

应用层是离用户最近的一层，也是我们每天都在直接打交道的一层。它不负责「数据怎么到对面」，只关心「说什么、怎么说」——数据如何编码、请求如何表达。底层可靠传输交给 TCP（见第 3、4 章）。

## 2.1 HTTP 报文：请求与响应

HTTP 是无状态、基于文本的请求-响应协议。报文分**请求**和**响应**两种，格式对称：

```
GET /index.html HTTP/1.1        ← 请求行：方法 + 路径 + 版本
Host: www.example.com           ← 首部（键值对）
User-Agent: curl/8.0
Accept: text/html

                                ← 空行结束首部
（可选的请求体，POST 才有）
```

| 请求方法 | 语义 | 幂等 |
|---|---|---|
| GET | 获取资源 | ✅ |
| POST | 提交数据、创建资源 | ❌ |
| PUT | 整体替换资源 | ✅ |
| DELETE | 删除资源 | ✅ |
| HEAD | 只取首部不取体 | ✅ |

| 状态码 | 类别 | 常见示例 |
|---|---|---|
| 1xx | 信息 | 100 Continue |
| 2xx | 成功 | 200 OK、201 Created、204 No Content |
| 3xx | 重定向 | 301 永久、302 临时、304 Not Modified |
| 4xx | 客户端错误 | 400、401 未认证、403 禁止、404 Not Found |
| 5xx | 服务器错误 | 500、502 网关、503 服务不可用 |

响应报文 = 状态行（版本 + 状态码 + 原因短语）+ 首部 + 空行 + 响应体。

## 2.2 DNS：把域名变成 IP

网络层只能按 IP 寻址（见第 5 章），但人记域名，所以需要**域名系统（DNS）** 做转换。DNS 是分层的、分布式的数据库：

```
根域名服务器（.）  →  顶级域服务器（.com）  →  权威服务器（example.com）
```

解析 `www.example.com` 的完整流程：

1. 查本机 hosts 文件、浏览器/DNS 缓存；
2. 未命中，向**本地 DNS 服务器**（递归查询）发起请求；
3. 本地服务器从**根**开始一路**迭代**：根 → `.com` 顶级域 → `example.com` 权威服务器；
4. 权威服务器返回 IP，本地服务器缓存后交给客户端。

> 对比：**递归查询**是「你替我去查到底」，客户端只问一次就得到最终结果（客户端→本地服务器这一段）；**迭代查询**是「我告诉你下一步问谁」，服务器只给下一跳地址，由查询方自己接力（本地服务器→各级服务器这一段）。递归把负担压在本地服务器，迭代把流程拆给各级各管一段——现实中两者混合使用。

## 2.3 电子邮件：SMTP / POP3 / IMAP

邮件系统分「发送」和「接收」两条链路，用不同的协议：

| 协议 | 作用 | 方向 | 端口 |
|---|---|---|---|
| SMTP | 发送/转发邮件 | 客户端→服务器、服务器→服务器 | 25/465/587 |
| POP3 | 下载邮件（默认下载后删除） | 服务器→客户端 | 110/995 |
| IMAP | 同步邮件（服务器留存，多设备同步） | 服务器↔客户端 | 143/993 |

- **SMTP 是「推」协议**，负责把邮件推到目标邮箱服务器；**POP3/IMAP 是「拉」协议**，负责把邮件从邮箱取回来。
- POP3 适合「单设备、本地保存」；IMAP 适合「多设备、云端同步」。

## 2.4 DHCP：自动分配 IP

**DHCP** 让主机无需手工配置 IP，接入网络即自动获得地址等参数。经典 **DORA** 四步：

| 步骤 | 报文 | 方向 | 内容 |
|---|---|---|---|
| Discover | DHCPDISCOVER | 客户端→广播 | 「有人能给我 IP 吗？」 |
| Offer | DHCPOFFER | 服务器→客户端 | 「我建议用这个 IP」 |
| Request | DHCPREQUEST | 客户端→广播 | 「我就要这个 IP」 |
| Ack | DHCPACK | 服务器→客户端 | 「成交，租约给你」 |

> 对比（为第 5 章埋钩子）：**IPv6 用 SLAAC（无状态自动配置）+ DHCPv6** 取代了 IPv4 的 DHCP 独大。SLAAC 让主机用前缀 + 自己生成的接口标识自动组地址，无需服务器；DHCPv6 则补充 DNS 等额外信息。第 5 章会详述 IPv6 地址。

> 对比（为 HTTP/2 埋钩子）：**HTTP/1.0** 每个请求都要新建一次 TCP 连接，请求完即断开；**HTTP/1.1** 引入**持久连接（keep-alive）**，一条连接可串行发多个请求，但仍有**队头阻塞**；**HTTP/2** 用**多路复用（multiplexing）** 在同一连接上并发多路请求，彻底消除队头阻塞。差异的根源都在「一条 TCP 连接怎么被复用」上。

> 承上启下：应用层把要传的数据准备好，剩下的「怎么可靠送到」就交给传输层。**下一章（第 3 章）进入传输层，看 TCP 和 UDP 这两条「传送带」的区别**；HTTP 报文的字节流，正是通过 TCP 的 socket 接口（第 9 章）发出去的。
