# 第 7 章 · 事务与并发控制

第 4 章末尾的 `BEGIN/COMMIT/ROLLBACK` 只给了语法。本章回答：**事务凭什么保证「要么全成、要么全不」，多事务同时跑时为什么不出乱子？**

## 7.1 ACID：事务的四个承诺

| 性质 | 含义 | 破坏者 |
|---|---|---|
| **A 原子性** | 事务内的操作要么全做、要么全不做 | 中途崩溃（第 8 章恢复解决） |
| **C 一致性** | 事务把库从一个一致状态带到另一个一致状态 | 约束被违反 |
| **I 隔离性** | 并发事务互不干扰，像串行执行 | 并发异常（本章主题） |
| **D 持久性** | 一旦提交，结果永久保存 | 掉电、介质损坏（第 8 章） |

原子性靠**回滚日志（undo）**，持久性靠**重做日志（redo）**——详见第 8 章。本章聚焦 **I（隔离性）** 与 **A/C 在并发下的维系**。

## 7.2 并发异常：不隔离会怎样

两个事务同时读写同一数据，可能出现四种异常：

| 异常 | 描述 | 示例 |
|---|---|---|
| **脏读** | 读到别的事务**未提交**的修改 | T2 读到 T1 改了但还没 commit 的余额 |
| **不可重复读** | 同一事务两次读，值被别的事务**改**了 | 两次读余额不一样 |
| **幻读** | 同一查询两次，行**集合**变了（多/少了行） | 第二次多出别的事务插入的行 |
| **丢失更新** | 两个事务都改同一值，一个覆盖另一个 | 两人同时扣款，一笔被吞 |

根因：事务交叉执行，破坏了「串行等价」。解决方案是**封锁**或 **MVCC**。

## 7.3 封锁：共享锁与排他锁

- **共享锁（S 锁，读锁）**：允许多个事务同时读，但不能写。
- **排他锁（X 锁，写锁）**：独享，读写都禁止他人。

```
        S 锁      X 锁
S 锁    ✅兼容    ❌冲突
X 锁    ❌冲突    ❌冲突
```

**两段锁协议（2PL）**：事务分「增长段」（只加锁）和「缩减段」（只放锁）两阶段，**先统一加锁、后统一释放**。遵守 2PL 能保证**可串行化**——并发执行的结果等价于某种串行顺序。但 2PL 只保证可串行化，**并不解决死锁**（死锁要靠死锁检测/超时/等待图解决）。

## 7.4 隔离级别：在正确性与性能间取值

标准定义四级隔离级别，从松到严：

| 级别 | 脏读 | 不可重复读 | 幻读 | 实现 |
|---|---|---|---|---|
| READ UNCOMMITTED | 可能 | 可能 | 可能 | 几乎不锁 |
| READ COMMITTED | 杜绝 | 可能 | 可能 | 读快照/行锁提交即放 |
| REPEATABLE READ | 杜绝 | 杜绝 | 可能* | 快照读 + 间隙锁 |
| SERIALIZABLE | 杜绝 | 杜绝 | 杜绝 | 全串行/严格 2PL |

*MySQL InnoDB 在 REPEATABLE READ 下靠**间隙锁（gap lock）**也基本杜绝幻读。隔离级别越高，一致性越强，**并发吞吐越低**——这是一笔显式权衡。

## 7.5 MVCC：多版本并发控制

MySQL InnoDB 与 PostgreSQL 都不靠「全程加锁」实现高隔离，而是 **MVCC（多版本并发控制）**：

```
undo 日志里保留每一行的历史版本，链成一个版本链
读事务看到的是「事务开始时刻的快照」——
  版本 trx_id ≤ 当前活跃最小事务号，且未被活跃事务修改
```

- **读不阻塞写、写不阻塞读**：读直接读旧版本，不用等写锁。
- 每行带隐藏列 `trx_id`（最后修改者）和回滚指针（指向 undo 里的旧版本）。
- 代价是**旧版本要留着**（undo 膨胀），且 MVCC 只解决读，**写-写冲突仍要靠锁**。

> 对比：四个隔离级别 + MVCC——**READ UNCOMMITTED** 几乎无保护、吞吐最高，仅适合「脏读无所谓」的场景；**READ COMMITTED** 是 Oracle/PG 默认，避免脏读但允许不可重复读；**REPEATABLE READ** 是 MySQL InnoDB 默认，靠**快照读 + 间隙锁**兼顾一致与吞吐，是 OLTP 的常用甜点；**SERIALIZABLE** 最安全但最慢，用严格 2PL 或全串行。InnoDB 的 MVCC 让「读」走快照免锁，是它能同时拿到高隔离和高并发的原因——**本质是用「多版本 + undo 空间」换「少加锁 + 高并发」**。

> 承上启下：本章解释了第 4 章 `COMMIT/ROLLBACK` 背后的隔离语义。**原子性/持久性**依赖的 undo/redo 日志，正是第 8 章故障恢复的主角；**间隙锁**与索引（第 9 章）直接相关——锁的是索引记录和索引区间；**MVCC 的多版本**也靠索引与 undo 链支撑。理解了隔离级别，第 10 章对比 MySQL 与 PostgreSQL 默认隔离级别的差异时，就知其所以然了。
