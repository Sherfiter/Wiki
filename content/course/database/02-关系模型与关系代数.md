# 第 2 章 · 关系模型与关系代数

第 1 章说关系模型胜出，理由在于它有**数学根基**。这一章把「关系」落到严格定义上，再讲清它的「运算」——关系代数。理解关系代数，才知道 SQL 每句背后在算什么。

## 2.1 关系、元组、属性、域

**关系（Relation）** 是一张表，但比「表」更严格：它是**笛卡尔积的一个子集**。

- **域（Domain）**：一组相同类型的值的集合，如 `学号域 = {S001, S002, ...}`。
- **元组（Tuple）**：表中的一行，是各属性值的有序组合。
- **属性（Attribute）**：表中的一列，给域起一个名字。
- **关系模式**：`R(A1, A2, ..., An)`，是关系的「型」，如 `Student(学号, 姓名, 系)`。

关系的三条基本性质：**列同质**（每列来自同一个域）、**行无序、列无序**（靠名字不靠位置）、**不能有重复元组**（这是集合语义，与 SQL 表的多重集语义不同）。

```
Student(学号, 姓名, 系)
┌──────┬──────┬────┐
│ S001 │ 张三 │ CS │   ← 一个元组
│ S002 │ 李四 │ EE │
└──────┴──────┴────┘
          ↑ 属性（域 = 所有合法学号）
```

## 2.2 码：候选码、主码、外码

- **候选码（Candidate Key）**：能唯一标识一个元组的最小属性组。可能有多个。
- **主码（Primary Key）**：从候选码中选一个，作为关系的默认标识，**不能为空**。
- **外码（Foreign Key）**：属性 F 在本关系不是码，但却是另一个关系的码；用来「引用」另一张表，是关系模型表达联系的手段。

```
Student(学号 PK, 姓名, 系)
SC(学号 FK, 课程号 FK, 成绩)   —— SC 的两个外码共同引用 Student 和 Course
```

「最小」很关键：`{学号, 姓名}` 也能唯一标识人，但去掉「姓名」仍唯一，所以它不是候选码——候选码不能有冗余属性。

## 2.3 三类完整性约束

| 约束 | 规则 | 违反示例 |
|---|---|---|
| 实体完整性 | 主码不能取空值 | 学生没有学号 |
| 参照完整性 | 外码要么为空，要么等于被参照表某主码值 | 选了不存在的课程号 |
| 用户定义完整性 | 语义约束（取值范围等） | 成绩 < 0 或 > 100 |

实体完整性保证「每一行都能被找到」；参照完整性保证「引用不悬空」；这两条 DBMS 自动强制，第 3 章的 `PRIMARY KEY`/`FOREIGN KEY` 就是它们的落地。

## 2.4 关系代数：五种基本运算

关系代数是对关系的**集合运算**，输入一个或多个关系，输出仍是关系。最常用六种：

| 运算 | 记号 | 作用 |
|---|---|---|
| 选择 σ | $\sigma_{\text{条件}}(R)$ | 挑**行**（按条件过滤元组） |
| 投影 π | $\pi_{\text{属性}}(R)$ | 挑**列**（去重） |
| 连接 ⋈ | $R \bowtie_{R.A=S.B} S$ | 按条件拼**两个关系** |
| 除 ÷ | $R \div S$ | 找「满足 S 全部」的元组 |
| 并 ∪ / 交 ∩ / 差 − | 集合运算 | 要求两关系**结构相容** |

```
σ_{系='CS'}(Student)          → 只保留 CS 的学生行
π_{姓名}(Student)             → 只剩「姓名」一列，且去重
Student ⋈_{学号=学号} SC      → 学生和选课按学号拼成宽表
```

**连接**是关系代数里最贵也最常用的运算，等价于「先做笛卡尔积，再做选择」；第 4 章的内/外连接、第 9 章的连接优化，源头都在这里。

**除（÷）** 最反直觉，但很有用：`SC ÷ Course` 求的是「选了**所有**课程的学生」——除运算专门回答「对全部的…」这类查询。

> 对比：关系代数 vs 关系演算——**关系代数**是**过程式**的，明确写「先选谁、再连谁」，对应 SQL 的执行顺序；**关系演算**（元组演算、域演算）是**声明式**的，只描述「我要满足条件的元组」，不写怎么算，是 SQL `WHERE` 的灵感来源。二者表达能力等价，SQL 正是「代数为内核、演算为外观」的混合体。
>
> 对比（埋钩子）：关系数据库 vs 非关系数据库——关系模型靠**表和值匹配**表达联系，强在一致性与复杂查询（关系代数/连接）；非关系数据库（文档、KV、图，见第 10 章）放弃部分一致性换扩展性。这一对比的完整展开留到第 10 章，届时会用本节的「码、约束、连接」作参照系。

> 承上启下：本章给关系模型立了「型」（关系模式、码、三类约束）和「运算」（关系代数）。**型**是第 5 章规范化的原材料（函数依赖就长在属性上）；**运算**是第 3、4 章 SQL 的数学原型——你会反复看到「SELECT 是投影、WHERE 是选择、JOIN 是连接」。先把这张运算表背下来，SQL 就只是它的英语而已。
