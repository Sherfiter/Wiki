# 第 1 章 · 数据库系统概述

数据库系统的核心问题只有一个：**如何把现实世界的信息可靠、独立、可共享地存进机器，并能高效地取出来。** 回答它，先要搞清数据是怎么被「建模」和「分层」的。本章给出全课程的地图，后面九章都是这张地图上的地名。

## 1.1 从文件系统到数据库系统

文件系统只能提供「按名字读写字节」，数据之间的关联、约束、并发访问都要应用自己扛。数据库系统（DBS）把这三件事下沉到一层专门的软件——**DBMS（数据库管理系统）**：

| 能力 | 文件系统 | 数据库系统 |
|---|---|---|
| 数据结构化 | 无，字节流 | 有（关系/文档/图） |
| 数据共享 | 难，各自私有 | 集中统一，多用户 |
| 一致性约束 | 应用自写 | DBMS 强制（主键/外键/检查） |
| 并发与恢复 | 应用自写 | 内置（事务、日志） |
| 数据独立性 | 无 | 三级模式两层映像保证 |

DBMS 屏蔽了存储细节，应用只面对**逻辑数据**，这就是「数据独立性」的来源。

## 1.2 数据模型：三种历史形态

**数据模型**是现实世界到机器世界的抽象规则，规定「数据怎么组织、怎么联系」。历史上三种代表：

```
层次模型                网状模型                关系模型
┌────────┐            ┌────────┐            表（二维结构）
│  系     │            │  系  ──┤            学生(学号,姓名,系)
│  │  │  │            │  │\    │            ┌────┬────┬────┐
│ 教  学  │            │ 教  学 │            │S001│张三 │ CS │
│  │      │            │  │    │            └────┴────┴────┘
│ 研     │            │ 研 ──┘            联系 = 公共属性(外键)
└────────┘            └────────┘
一对多树，父子指针     多对多网，指针链      集合代数，值匹配
```

- **层次模型**：记录组织成树，一个双亲多个子女；表达「一对多」自然，但「多对多」要引入冗余节点，且必须从根遍历才能定位。
- **网状模型**：记录组成图，用指针链（系/Set）表达任意联系；表达能力强，但指针密布、程序员要自己导航，学习成本高。
- **关系模型**：一切是**表**，联系靠**值相等**（外键）而非指针；有坚实的数学基础（关系代数），SQL 声明式查询。

## 1.3 三级模式与两级映像

ANSI/SPARC 把数据库从里到外分成三层，中间用两层「映像」解耦：

```
外部层   外模式1(视图A)   外模式2(视图B)   ← 每个应用的视角
              │ 外模式/模式映像            ← 逻辑独立性
概念层   模式（全局逻辑结构）                ← 全库唯一的逻辑视图
              │ 模式/内模式映像            ← 物理独立性
内部层   内模式（存储结构、索引、物理文件）  ← 磁盘上的样子
```

- **外模式（子模式/视图）**：单个用户看到的数据，可隐藏、可裁剪。
- **模式（概念模式）**：全库的逻辑结构——有哪些表、什么约束，不关心物理存储。
- **内模式（存储模式）**：数据怎么存、用什么索引、聚簇与否（见第 9 章）。

两层映像各保证一种独立性：**逻辑独立性**（改模式不改外模式，应用无感）、**物理独立性**（改内模式不动模式，如加索引、换存储）。

## 1.4 DBMS 的组成

```
用户/应用
   │ SQL
┌──▼──────────────┐
│ 查询处理器       │ 解析 → 优化 → 执行（见第 9 章）
├─────────────────┤
│ 存储管理器       │ 缓冲池、文件组织、索引
├─────────────────┤
│ 事务管理器       │ 并发控制（第 7 章）、故障恢复（第 8 章）
├─────────────────┤
│ 数据字典         │ 元数据：表结构、约束、索引定义
└─────────────────┘
```

查询处理器把声明式 SQL 翻译成执行计划；事务管理器保证 ACID（见第 7 章）；数据字典存「关于数据的数据」，三级模式就登记在这里。

> 对比：层次 / 网状 / 关系三模型——**层次**结构最简、遍历快，但僵化、多对多别扭；**网状**表达力最强、指针直连快，但程序员负担重、难维护；**关系**以数学为基础、声明式查询、独立性最好，代价是理论开销（连接、规范化见第 5 章）。三者是「简单 → 灵活 → 抽象」的演进：越晚出现，越把复杂性从「程序员写指针」转移到「DBMS 做优化」。

> 承上启下：本章是整门课的坐标系。**数据模型**的结论——关系模型胜出——直接引出第 2 章的关系代数和第 3、4 章的 SQL；**三级模式**中的「内模式/索引」是第 9 章的主场；**事务管理器**的职责拆成第 7（并发）与第 8（恢复）两章。后面每章都能在「查询处理器 / 存储管理器 / 事务管理器」这张图上找到自己的位置。
