# 第 7 章 · 存储层次与 Cache

CPU 越来越快，内存却没跟上——这个「内存墙（memory wall）」靠**存储层次**来弥合：用小块高速存储挡住大部分内存访问。本章先讲它成立的前提（局部性原理），再讲 Cache 的三件套：映射方式、替换策略、写策略。第 8 章把同样的思想推到虚拟内存，两层互为镜像。

## 7.1 局部性原理

Cache 有效的前提是程序访问内存**不均匀**：

- **时间局部性**：刚访问过的地址，很快会再访问（循环变量、热代码）。
- **空间局部性**：访问过某地址，很快会访问它附近的地址（数组顺序扫描、指令顺序执行）。

```c
for (int i = 0; i < n; i++)        // i：时间局部（反复读）
    sum += a[i];                    // a[i]：空间局部（连续读）
```

> 注意：**局部性是「程序的统计规律」，不是硬件保证**。链表遍历、哈希表随机访问就是「反局部性」的——`p = p->next` 每次跳到一个随机堆地址，空间局部性差，Cache 命中率暴跌。这就是为什么「数组 vs 链表」遍历性能差一个数量级，根子在第 5 章 C 指针课程的连续内存 vs 指针跳跃，也在本章的 Cache 行。

## 7.2 存储层次与命中

从快到慢、从小到大：

```text
寄存器 < L1 Cache < L2 < L3 < 主存 < 磁盘
  ~0.3ns    ~1ns    ~4ns  ~12ns  ~100ns   ~10ms
```

衡量 Cache 的指标：

```
平均访存时间 = 命中时间 + 缺失率 × 缺失代价
```

**缺失代价（miss penalty）** = 从下一层取数的延迟，通常远大于命中时间，所以**降低缺失率**是 Cache 设计的第一目标。

## 7.3 三种映射方式

内存地址被切成 `标记 Tag | 索引 Index | 块内偏移 Offset`。三种映射决定「一个内存块能放到 Cache 的哪个位置」：

| 映射 | 规则 | 查找方式 | 冲突缺失 | 硬件 |
|---|---|---|---|---|
| 直接映射 | 每块固定放唯一位置（Index 决定） | 只查 1 个位置 | 高（同 Index 不同 Tag 互踢） | 最简单 |
| 全相联 | 可放任意位置 | 并行查所有 Tag（内容寻址） | 无冲突缺失 | 最贵（CAM） |
| 组相联 | 先按 Index 定组，组内任意 | 查一组（如 8 路）的 Tag | 介于两者 | 折中，主流 |

```text
直接映射：  块只能进它唯一的那一格
组相联(8路)：块进它所属组的 8 格之一
全相联：    块能进任何一格
```

> 对比：三者的权衡是「**命中率 vs 查找成本**」。直接映射便宜但同 Index 的不同块会互相驱逐（抖动摇摆）；全相联零冲突但需要内容寻址存储器（CAM）并行比较所有 Tag，面积功耗爆炸；**组相联（尤其 8 路、16 路）是工程甜点**——现代 CPU L1 常用 8 路、L2/L3 用 16 路甚至更高。

## 7.4 替换策略

组相联/全相联里，组满时新块要**踢掉一个旧块**：

| 策略 | 规则 | 特点 |
|---|---|---|
| 随机 | 随机踢一个 | 简单，命中率不稳定 |
| FIFO | 踢最早进来的 | 简单，但可能踢掉热点（Belady 异常） |
| LRU | 踢最久没用的 | 贴合时间局部性，命中率高，但硬件要记录访问顺序 |

> 注意：**LRU 是理论最优，但硬件实现代价随路数指数增长**（要记录 N! 种顺序）。实际工程用**近似 LRU**（如树形伪 LRU，每路几个 bit 记录「最近用过」），在几路 Cache 里用很小的硬件成本逼近 LRU。缓存越大、路数越多，越用近似算法。

## 7.5 写策略：写直达 vs 写回

读缺失好办（去下一层取），**写**才是 Cache 一致性的麻烦——因为写会同时改 Cache 和主存：

| 策略 | 写命中时 | 写缺失时 | 特点 |
|---|---|---|---|
| 写直达（write-through） | 同时写 Cache 和主存 | 写分配 / 写不分配 | 主存永远新，简单，但每次写都访存 |
| 写回（write-back） | 只写 Cache，标 dirty | 写分配为主 | 主存延迟到被替换时才写，省带宽 |

- **写分配 vs 写不分配**：写缺失时，要不要先把块从主存调入 Cache？「写回」通常配**写分配**（写局部性，块很快还会写）；「写直达」可配写不分配。
- **写缓冲（write buffer）**：写直达每次写都要访存，慢；加一个缓冲队列，CPU 写完缓冲就继续，缓冲在后台慢慢写主存——代价是读缺失时可能要等缓冲排空。

> 对比：**写直达简单、一致性好，但带宽浪费；写回省带宽、快，但要 dirty 位和替换时写回**。多核下 Cache 一致性（coherence）更复杂——写回策略下多个核的 Cache 各持一份脏数据，要靠 MESI 之类协议同步（第 8 章/OS 并发的延伸）。CPU 内部 Cache 普遍用写回，I/O 设备映射内存（第 9 章）有时强制写直达。

## 7.6 与虚拟内存 / 语言对照

- **第 8 章**：Cache 与虚拟内存是**同一思想的两种尺度**——Cache 弥合「CPU 与主存」的速度差，虚拟内存弥合「主存与磁盘」的容量差。映射方式（组相联 vs 页表）、替换策略（LRU vs 页面置换）、写策略（写回 vs 写时复制）一一对应。
- **C**：数组顺序访问吃满空间局部性；结构体字段紧邻、`struct` 小字段打包也利于 Cache 行。**多线程伪共享（false sharing）**：两个线程写同一 Cache 行的不同变量，互相失效对方的行，性能雪崩——这是 Cache 行粒度（64B）直接影响程序性能的典型。
- **Java/Python**：对象在堆上散落，引用数组（第 5 章 C 指针的指针数组）遍历比连续数组慢，本质就是 Cache 局部性差。

> 承上启下：**局部性让「小快 Cache + 大慢内存」的组合接近「全快内存」的体验；映射定位置、替换定去留、写策略定一致性，三者共同决定平均访存时间。** 下一章把这个思想推到「主存-磁盘」尺度，就是虚拟内存。
