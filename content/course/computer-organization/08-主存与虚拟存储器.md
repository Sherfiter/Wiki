# 第 8 章 · 主存与虚拟存储器

第 7 章用 Cache 挡在 CPU 和主存之间，本章下沉到「主存本身怎么造（DRAM）」以及「主存不够怎么办（虚拟内存）」。虚拟内存是第 7 章存储层次思想在「主存-磁盘」尺度上的复刻，也是操作系统内存管理（OS 第 6 章）的硬件底座——本章在两者之间搭桥。

## 8.1 SRAM vs DRAM

两种 RAM 的工艺分岔，决定了它们在层次结构里的位置：

| | SRAM | DRAM |
|---|---|---|
| 存储单元 | 6 个晶体管（触发器） | 1 晶体管 + 1 电容 |
| 刷新 | 不需要 | **要周期刷新**（电容漏电） |
| 速度 | 快（纳秒级） | 慢 |
| 密度/成本 | 低/贵 | 高/便宜 |
| 用途 | Cache（第 7 章） | 主存 |

> 注意：DRAM 的电容会漏电，必须每隔几十毫秒**刷新**一次（重写一遍所有行），否则数据消失。刷新会占用访存带宽——这就是「DRAM 延迟不稳定、且比 SRAM 慢一个量级」的物理根源，也是 Cache 必须存在的原因（第 7 章内存墙）。

## 8.2 DRAM 的组织与访存

DRAM 是**二维阵列**，地址被拆成**行地址 + 列地址**，通过 RAS/CAS 两根选通信号分时复用同一组地址线（省引脚）：

```text
访存流程：先 RAS 选行（整行读入行缓冲/感测放大器）
          再 CAS 选列（从行缓冲里挑出目标单元）
```

由此衍生出 DRAM 的时序概念：**行缓冲命中（row buffer hit）**——连续访问同一行（空间局部性！）就快，跨行访问要重新激活，慢得多。SDRAM/DDR 的「DDR（双倍数据率）」= 时钟上下沿都传数据，带宽翻倍。

> 对比：**DRAM 的「行/列」组织是空间局部性在硬件层的体现**——顺序访问数组 = 同一行连续列，快；随机访问 = 频繁换行，慢。这和第 7 章 Cache 的局部性是一套逻辑：**从 CPU 寄存器到磁盘，每一层都在奖励顺序、惩罚随机。**

## 8.3 虚拟内存：把磁盘当主存用

虚拟内存的核心：**每个进程看到一个独立、连续、比物理内存大的「虚拟地址空间」**，由硬件（MMU）+ 操作系统共同翻译成物理地址。

- **分页**：地址空间切成固定大小的**页（page，通常 4KB）**，物理内存切成等大的**页框（frame）**。虚拟页 ↔ 物理页框的映射存在**页表（page table）**里。
- **页表项（PTE）**：含物理页框号、有效位（在不在内存）、dirty 位（被写过没）、访问位（用于替换）、权限位（读/写/执行）。

```text
虚拟地址 = 虚拟页号 VPN | 页内偏移 offset
              │ 查页表（MMU + TLB）
              ▼
物理地址 = 物理页框号 PFN | 页内偏移 offset（不变）
```

- **缺页（page fault）**：访问的页不在物理内存（有效位=0），触发异常，OS 从磁盘换入（第 9 章的中断/DMA 联动）。
- **页置换**：物理内存满时，OS 按 LRU/时钟算法踢一个页——这正是第 7.4 节 Cache 替换策略的放大版。

> 注意：虚拟内存给每个进程「独占整块内存」的错觉，是**进程隔离**和**安全**的硬件基石——一个进程的虚拟地址只有经过自己的页表才能落到物理地址，无法直接窥探别的进程。这也是 C 指针课程「野指针访问非法地址 → SIGSEGV」的机制：MMU 发现该虚拟页无映射或无权限，触发缺页/保护异常，内核发段错误信号。

## 8.4 TLB：页表的 Cache

查页表本身要访存（页表可能在主存，多级页表要多次访存），慢。**TLB（快表，Translation Lookaside Buffer）** 就是「虚拟页号 → 物理页框号」的专用 Cache：

```text
CPU 发虚拟地址 ──▶ 先查 TLB（快，命中则直接得物理地址）
                    │ 未命中 ──▶ 查页表（慢）──▶ 装入 TLB
```

> 对比：**TLB 之于页表，正如 Cache 之于主存**——都是「小快缓冲挡在大慢结构前面」，都用局部性（TLB 命中靠时间局部性：程序反复访问同一批页）。所以「TLB 缺失 → 查页表 → 可能缺页 → 换页」，是一条越来越慢的链条，和第 7 章「Cache 缺失 → 主存」同构。

| 层次 | 挡在谁之间 | 缓冲什么 | 缺失代价 |
|---|---|---|---|
| Cache | CPU ↔ 主存 | 内存块 | 主存延迟 |
| TLB | MMU ↔ 页表 | 页表项 | 页表访存 |
| 页表 | 进程 ↔ 物理内存 | 虚拟↔物理映射 | 缺页（磁盘！） |

## 8.5 与操作系统 / 各章衔接

- **OS 第 6 章（内存管理）**：本章的页表、缺页、页置换，正是操作系统内存管理章节的硬件基础——OS 负责「页表内容、置换策略、缺页处理」，硬件负责「MMU 地址翻译、TLB、权限检查」。**本课程讲「怎么做」，OS 讲「如何调度」**，互为表里。
- **OS 第 7 章（文件/设备）**：`mmap` 把文件映射进虚拟地址空间，本质是「让文件页按需从磁盘换入」，是虚拟内存思想在文件 I/O 上的复用。
- **第 9 章**：缺页是「异常 → 中断服务 → 从磁盘 DMA 读入 → 恢复进程」的完整流程，串起了中断与 DMA。
- **C/Java**：`malloc`/`new` 分配的是**虚拟地址**，物理页可能到真正读写时才分配（惰性分配）；Java 的 GC、Python 的引用计数，都运行在这套虚拟内存之上。

> 承上启下：**SRAM 做 Cache、DRAM 做主存、磁盘做后备，虚拟内存用页表把三者缝合成一个统一的地址空间，TLB 再给页表套一层 Cache——整个存储体系是「局部性」与「翻译」层层叠加的结果。** 存储讲完，剩下最后一块：数据如何进出计算机（第 9 章 I/O）。
