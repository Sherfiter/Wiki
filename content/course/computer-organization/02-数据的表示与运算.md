# 第 2 章 · 数据的表示与运算

计算机里没有「数」，只有**位**。本章解决两件事：整数怎么用有限位表示（原码/反码/补码），以及实数怎么用二进制逼近（IEEE 754 浮点）。这两个约定直接决定第 3 章 ALU 的运算器设计，也是 C 语言里 `unsigned` 陷阱、浮点精度丢失的机器级根源。

## 2.1 进制与位权

一切进制都是**位权展开**：任意 R 进制数 `d_n…d_1d_0` 的值 = `Σ d_i × R^i`。

- **二进制 → 十六进制**：4 位一组（因为 16=2⁴），`1010 1110 = 0xAE`。这是最常用的换算，因为一个字节正好两个十六进制位。
- **十进制 → 二进制**：整数「除 2 取余，逆序」；小数「乘 2 取整，顺序」。
- **小数二进制陷阱**：`0.1`（十进制）转二进制是**无限循环小数** `0.0001100110011…`。所以 `0.1` 在计算机里根本无法精确表示——这是浮点误差的源头（见 2.4）。

> 注意：进制换算的「精度」是另一回事——二进制表示十进制小数**不保证精确**，但「二进制→十六进制」这种 2 的幂次换算是无损的，纯粹是位分组，没有任何舍入。

## 2.2 原码、反码、补码

负数三种表示法（以 8 位为例，`-5`）：

| 表示 | `-5` 的编码 | 正数区 | 零的表示 | 关键性质 |
|---|---|---|---|---|
| 原码 | `1000 0101` | 最高位是符号 | `0000 0000` 和 `1000 0000` 两个零 | 人读直观，但加减法要判符号，硬件复杂 |
| 反码 | `1111 1010` | 按位取反 | 两个零 | 减法仍要处理「循环进位」，未根本解决 |
| 补码 | `1111 1011` | 反码+1 | 只有一个零 | 减法=加法，硬件只需加法器 |

**为什么补码是唯一正确解**：

1. **唯一零**：原码/反码都有 `+0` 和 `-0` 两个编码，浪费一个编码位且比较逻辑要特判；补码零唯一，`1000 0000` 被解放出来表示 `-128`，所以 8 位补码范围是 `-128 ~ +127`（不对称，多一个负数）。
2. **减法变加法**：补码的本质是**模运算**。n 位补码的模是 2ⁿ，`-x ≡ 2ⁿ - x (mod 2ⁿ)`。`A - B = A + (2ⁿ - B) = A + (-B)`，溢出位自然丢弃。硬件不用造减法器。
3. **符号位参与运算**：补码加法最高位直接当数值位一起算，结果符号自动正确；原码/反码必须单独处理符号。

> 对比：`-x` 的补码 = 「取反加一」。反过来 `x` 的补码求负也成立（`-(-x)=x`）。求补码的机器捷径：从右往左找到第一个 1，它左边的所有位取反，右边不动——`-5` 原码 `0000 0101`，第一个 1 左边 `0000 010` 取反得 `1111 101`，拼上右边 `1` = `1111 1011`。

```text
求 -5 的补码（8 位）：
  +5 = 0000 0101
  取反 = 1111 1010
  加一 = 1111 1011   ← -5
```

## 2.3 定点数与溢出判定

**定点数**：小数点位置固定，整数只是小数点在最右端的特例。定点运算溢出（结果超出可表示范围）必须检测，两条等价判据：

1. **进位判据**：符号位的进位 `C_out` 与次高位的进位 `C_in` 不同，即溢出。`V = C_out ⊕ C_in`。
2. **双符号位判据**：用两位符号位（如 `00`=正、`11`=负）参与运算，结果两位符号位不同（`01` 或 `10`）即溢出。

```text
8 位补码加法溢出示例：
  +100  (0110 0100)
+ +50   (0011 0010)
= +150  (1001 0110)  ← 符号位变成 1，结果却是 +150 > 127，溢出！
```

> 注意：C 语言的 `int` 溢出是**未定义行为（UB）**，编译器可能做任何事（包括把循环优化掉）；而 `unsigned` 溢出是**明确定义的模 2ⁿ 回绕**。同一个「溢出」在 C 语义层含义不同，别把「补码回绕」当成「int 安全溢出」。

## 2.4 浮点数：IEEE 754

实数用**科学计数法**逼近：`(-1)^s × 1.fraction × 2^(exponent - bias)`。

单精度（float，32 位）与双精度（double，64 位）的位布局：

| 精度 | 符号 s | 指数 e | 尾数 fraction | bias | 范围量级 |
|---|---|---|---|---|---|
| float | 1 位 | 8 位 | 23 位 | 127 | ~10⁻³⁸ ~ 10³⁸ |
| double | 1 位 | 11 位 | 52 位 | 1023 | ~10⁻³⁰⁸ ~ 10³⁰⁸ |

要点（这是浮点最「非显然」的部分）：

- **规格化与隐藏位**：尾数第一位永远是 `1`（规格化数），所以不存，白赚 1 位精度。指数存的是**偏置值**（真值 + bias），这样指数比较时可以直接按无符号整数比大小，硬件简单。
- **特殊值**：指数全 0 + 尾数全 0 = **±0**；指数全 1 + 尾数全 0 = **±∞**；指数全 1 + 尾数非 0 = **NaN**（Not a Number）。`0.0` 和 `-0.0` 是不同编码，但比较相等。
- **非规格化数（denormal）**：指数全 0、尾数非 0 时，隐藏位变成 0，用于表示比最小规格化数更接近 0 的数——填平了「突然下溢到 0」的鸿沟（gradual underflow）。
- **舍入**：超出尾数精度的位按最近舍入（round-to-nearest, ties-to-even）丢弃。第 2.1 节的 `0.1` 就是无限循环小数，被舍入成最接近的近似值。

```text
0.1 (double) 的实际存储值 ≈ 0.1000000000000000055511151231257827...
所以 0.1 + 0.2 != 0.3  （结果是 0.30000000000000004）
```

> 对比：定点 vs 浮点的本质权衡——**定点**小数位固定，范围小但精度均匀、运算快（纯整数电路，第 3 章）；**浮点**用指数换来巨大动态范围，但精度**不均匀**（越大的数间隔越疏，有效位数固定为 24/53 位）。金融、计时等要求精确十进制小数（且无舍入）的场景，绝不能用二进制浮点，要用定点或十进制库。

## 2.5 与运算器 / C 语言对照

- **第 3 章**：补码让 ALU 只用加法器就能做减法；溢出标志 OF 用的正是 2.3 的 `C_out ⊕ C_in` 判据。浮点加减则是「对阶 → 尾数运算 → 规格化 → 舍入」四步，比整数加法慢得多。
- **C**：`float`/`double` 对应 IEEE 754；`int`/`unsigned` 对应补码。`(int)0.1` 截断、浮点比较不能用 `==`、`1/0.0` 得 `inf` 而 `0.0/0.0` 得 `NaN`，根源全在本章。
- **Java**：`int` 溢出与 C 不同——Java 的 `int` 是**明确定义**的补码回绕（不像 C 是 UB）；`double` 完全遵循 IEEE 754。
- **Python**：`int` 是**任意精度**大整数（内部用数组存位），不会溢出，代价是慢；`float` 仍是 IEEE 754 double，所以 `0.1+0.2` 的问题照旧。

> 承上启下：**整数用补码（模运算、唯一零、减法=加法），实数用 IEEE 754（符号+偏置指数+隐藏位尾数，动态范围换精度）。** 这是后面所有运算器（第 3 章）与程序正确性问题的根。
