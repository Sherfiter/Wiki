# 第 10 章 · 汇编与程序运行

前九章从位、ALU、指令、CPU、存储一路讲下来，全是「机器怎么转」。本章把镜头拉回到程序：**一段 C 代码，如何经过汇编、调用约定、栈帧，最终变成 CPU 真正执行的指令序列**。这一章是整门课的收束，也把 C 指针课程第 2 章「栈帧」的伏笔闭环。

## 10.1 x86-64 汇编基础

**语法**有两大方言，务必分清（`gcc -S` 默认 AT&T，`objdump -d` 也是）：

| | AT&T | Intel |
|---|---|---|
| 操作数顺序 | 源在前，目的在后 `mov %rax, %rbx` | 目的在前 `mov rbx, rax` |
| 寄存器前缀 | `%rax` | `rax` |
| 立即数前缀 | `$5` | `5` |
| 内存寻址 | `(%rbx)` | `[rbx]` |
| 大小后缀 | `movq`/`movl` | `mov qword ptr` |

**通用寄存器**（64 位 rax、rbx、rcx、rdx、rsi、rdi、rbp、rsp、r8~r15；低 32 位是 eax、ebx……）。约定俗成的角色（见 10.3）：

```x86asm
mov rax, [rbx+8]     ; rax = *(rbx + 8)，变址寻址（第 4.2 节）
lea rax, [rbx+rcx*4] ; rax = rbx + rcx*4，只算地址不访存
add rax, rbx          ; rax += rbx，置标志位（第 3.6 节）
cmp rax, rbx          ; 比较 = 减法，只置标志位不写回
jne target            ; ZF==0 则跳（相对寻址，第 4.2 节）
```

> 注意：`lea`（Load Effective Address）是「只算地址、不读内存」——它常被编译器滥用来做**纯算术**（`lea rax, [rbx+rbx*4+3]` 一次算 `5x+3`），因为不碰标志位、不访存，比 `mul`+`add` 快。这印证第 3.5 节「乘法很贵，编译器用移位/lea 替代」的观察。

## 10.2 从 C 到机器码：编译的最后一公里

```c
int square(int x) { return x * x; }
```

编译成汇编（`gcc -O2 -S`）大致是：

```x86asm
square:
    imul  edi, edi    ; x *= x（参数 x 已在 edi，第 1 参数寄存器）
    mov   eax, edi    ; 返回值放 eax
    ret               ; 弹出返回地址，跳回调用者
```

要点：**一条 C 语句可能对应几条、也可能零条指令**（被优化掉）；变量名消失，只剩寄存器/栈偏移；`return` 就是把结果塞进 `eax` 再 `ret`。这是 C 指针课程「变量名在机器层就是偏移」那句的汇编实锤。

## 10.3 调用约定：System V AMD64 ABI

函数调用是「调用者与被调者的协议」，x86-64 Linux 的标准约定（ABI）：

- **参数传递**：前 6 个整型参数依次放 `rdi, rsi, rdx, rcx, r8, r9`；第 7 个起放**栈上**（第 2 章栈帧图里 `[rbp+16]` 起）。
- **返回值**：整数/指针放 `rax`（64 位）或 `eax`（32 位）。
- **被调用者保存寄存器（callee-saved）**：`rbx, rbp, r12~r15`——被调函数若要用，必须先保存、退出前恢复。
- **调用者保存寄存器（caller-saved）**：`rax, rcx, rdx, rsi, rdi, r8~r11`——调用者若在乎其值，必须在 `call` 前自己保存。
- **栈对齐**：`call` 前 `rsp` 必须 16 字节对齐（进入函数时 `rsp+8` 是 16 的倍数）。
- **红区（red zone）**：`rsp` 下方 128 字节是给被调函数免 `sub rsp` 直接用的临时区（叶子函数优化）。

> 对比：**caller-saved vs callee-saved** 的分工是「谁保存谁负责」——编译器尽量把「跨调用还活着的值」放进 callee-saved 寄存器（被调者会保存），把「一次性临时值」放进 caller-saved（调用者不管）。这就是为什么写内联汇编时，改了 `rbx` 必须先 push，改 `rax` 则不必。

## 10.4 栈帧的完整闭环（回扣 C 指针第 2 章）

本课程的栈帧机制，与 C 指针课程第 2 章「程序的内存布局与栈帧」是**同一件事的两个视角**——那边从 C 看，这边从汇编看：

```x86asm
; 函数序言（prologue）
push rbp          ; ① 保存调用者 rbp
mov  rbp, rsp     ; ② 建立自己的帧底
sub  rsp, 16      ; ③ 为局部变量留 16 字节

; ... 函数体：局部变量 [rbp-4]、参数 [rbp+8/16/...]

; 尾声（epilogue）
mov  rsp, rbp     ; ④ 丢弃局部变量
pop  rbp          ; ⑤ 恢复调用者 rbp
ret               ; ⑥ 弹出返回地址，跳回
```

这六步，就是 C 指针课程第 2 章那张栈帧图的机器级逐条翻译：

- `call` 压返回地址（`[rbp+8]`）、`ret` 弹回——对应那边「返回地址」。
- 局部变量 `sub rsp, N` 一次留出、`mov rsp, rbp` 一次全丢弃——对应那边「局部变量生命周期 = 函数调用期间」。
- **返回局部变量地址悬空**（那边 2.5 节）：`ret` 后 `rsp` 弹回，`[rbp-4]` 已被「归还」，下次 `call`/`push` 就覆盖——这正是那边「悬空指针机器级本质」的完整闭环。

> 注意：开了 `-O2`，编译器可能**省略帧指针**（`-fomit-frame-pointer`），不用 `rbp`、直接用 `rsp` 寻址，省一个寄存器、少两条序言指令——「栈帧」此刻是**纯约定**，不是硬件结构。这呼应 C 指针第 2 章 2.7 节「帧是 ABI 约定，不是硬件概念」。
