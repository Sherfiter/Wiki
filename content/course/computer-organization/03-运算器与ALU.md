# 第 3 章 · 运算器与 ALU

第 2 章定义了「数怎么表示」，本章讲「数怎么算」。核心是加法器——因为补码把减法变成加法（第 2.2 节），所以**加法器是整个 ALU 的心脏**。本章沿「一位全加器 → 多位加法器（串行 vs 超前）→ ALU → 移位 → 乘除 → 标志位」推进。

## 3.1 一位全加器（Full Adder）

一位加法有三个输入（两个加数位 a、b，低位进位 cin）、两个输出（和 s、进位 cout）：

```
s    = a ⊕ b ⊕ cin
cout = (a ∧ b) ∨ (cin ∧ (a ⊕ b))     // 至少两个 1 就产生进位
```

**半加器**只处理 a、b 两位无低位进位；把 n 个全加器串起来，cin 接上一级的 cout，就是 n 位**行波进位加法器**（ripple-carry adder）。

## 3.2 行波进位 vs 超前进位

**行波进位加法器**：进位从最低位逐级「滚」到最高位，第 i 位的和要等第 i-1 位的进位。延迟 = n × 单级进位延迟，**n 位加法最坏 O(n)**。结构简单、面积小，但位数一大就成了关键路径（第 1 章讲的 critical path）。

**超前进位加法器（CLA, Carry Lookahead Adder）**：并行预计算所有进位。定义两个信号：

- **生成 gᵢ** = aᵢ ∧ bᵢ：本位自己能产生进位。
- **传播 pᵢ** = aᵢ ⊕ bᵢ：低位进位来了能「传过去」。

则 `cᵢ₊₁ = gᵢ ∨ (pᵢ ∧ cᵢ)`，展开就是：

```text
c1 = g0 ∨ (p0 ∧ c0)
c2 = g1 ∨ (p1 ∧ g0) ∨ (p1 ∧ p0 ∧ c0)
c3 = g2 ∨ (p2 ∧ g1) ∨ (p2 ∧ p1 ∧ g0) ∨ (p2 ∧ p1 ∧ p0 ∧ c0)
...
```

所有进位只依赖 g、p 和 c0，**一层门电路同时算出**，延迟 O(log n) 量级。

> 对比：**串行 vs 并行是贯穿全课程的主题**（第 6 章流水线、第 7 章 Cache 都是同一思想）。CLA 用「额外电路 + 门扇入」换「延迟」。实际工程是折中——**分组超前进位**：组内 CLA、组间再串行（或两级 CLA），既不大面积爆炸，又把延迟压到可接受。

| 加法器 | 延迟 | 面积/扇入 | 适用 |
|---|---|---|---|
| 行波进位 | O(n) | 最小 | 面积优先、位数短 |
| 全 CLA | O(log n) | 大、高扇入 | 延迟优先 |
| 分组 CLA | 介于两者 | 折中 | 主流 |

## 3.3 ALU：加法的「加强版」

**ALU（算术逻辑单元）** 在加法器外围加选择逻辑，用**功能选择线**切出多种运算：

```text
      ┌───────────┐
A ───▶│           │
B ───▶│   ALU     │──▶ 结果 F
op ──▶│           │──▶ 标志位 ZF/OF/CF/SF
      └───────────┘
```

一个 n 位 ALU 至少支持：加、减（A + 补码(B)）、按位与/或/异或、非、比较（减但不写回结果，只置标志位）、移位。**减法就是「B 取反 + cin=1」**——反相器把 B 取反，最低位进位置 1，恰好等于加 B 的补码。

## 3.4 移位运算：逻辑 / 算术 / 循环

| 移位 | 操作 | 空位补 | 用途 |
|---|---|---|---|
| 逻辑左移 SLL | 整体左移 | 补 0 | `x << 1` = 乘 2 |
| 逻辑右移 SRL | 整体右移 | 补 0 | `unsigned` 除 2 |
| 算术右移 SRA | 右移 | **补符号位** | `signed` 除 2（保符号） |
| 循环移位 ROL/ROR | 移出的位补到另一端 | 自身 | 位旋转、密码学 |

> 注意：**算术右移 vs 逻辑右移是 C 里 `int >> 1` 与 `unsigned >> 1` 的机器级区别**。C 标准规定有符号数右移是「实现定义」——主流编译器对负数用算术右移（补符号位），所以 `-5 >> 1 = -3`（向负无穷取整）；无符号数一律逻辑右移。左移对负数溢出是 UB（第 2 章）。

移位器是**组合逻辑**，用「桶形移位器（barrel shifter）」一次移任意位数，乘法里用移位+加法替代乘常数（`x*10 = (x<<3)+(x<<1)`）。

## 3.5 乘法与除法

**乘法**：本质是「移位 + 累加」。手算乘法按乘数每位决定「加被乘数或加 0」，再左移一位：

```text
  1101  (13)
×  1011  (11)
─────────────
  1101   ← 乘数最低位为 1，加
 1101    ← 左移 1 位再加
0000     ← 该位为 0，加 0
1101     ← 左移 3 位再加
─────────────
10001111 (143)
```

硬件用 **Booth 算法**处理有符号乘法：对补码同样有效，且遇到连续的 1（如 `…01110…`）能一次跳过、减少加/减次数。现代 CPU 用阵列乘法器或华莱士树（Wallace tree）并行压缩部分积，单周期或几周期出结果。

**除法**：本质是「移位 + 比较 + 减」。恢复余数法：试减除数，够减商 1，不够减商 0 并**恢复**（加回除数）；**不恢复余数法**省掉「恢复」这一步，用符号控制下一步加减，是实际硬件的主流。

> 对比：乘除法比加减慢得多——整数加法 1 个周期，整数乘法常 3~4 周期，整数除法可达 20~90 周期（x86 上 `div` 极慢）。所以编译器会把「除以常数」优化成「乘以倒数 + 移位」（如 `x/10 ≈ (x × 0xCCCCCCCD) >> 35`），避免真正的除法指令。这是「看似一条 C 语句，底层代价天差地别」的典型。

## 3.6 标志位：ZF / OF / CF / SF

ALU 运算后置一组**条件码标志位**（x86 的 EFLAGS），供条件跳转读取：

| 标志 | 含义 | 置位条件 |
|---|---|---|
| ZF | 零标志 | 结果为 0 |
| SF | 符号标志 | 结果最高位（符号位）为 1 |
| CF | 进位/借位标志 | **无符号**运算产生进位或借位（C_out） |
| OF | 溢出标志 | **有符号**运算溢出（第 2.3 节 `C_out ⊕ C_in`） |

> 注意：**CF 与 OF 分别服务「无符号」和「有符号」两种解释**——同一串位 `1111 1111 + 0000 0001`，当无符号数是 255+1=256 进位（CF=1），当有符号数是 -1+1=0 不溢出（OF=0）。CPU 同时置两个标志，**由指令的语义决定看哪个**：`ja/jb`（above/below）看 CF，`jg/jl`（greater/less）看 OF 和 SF。这就是为什么 C 里 `unsigned` 比较和 `signed` 比较会编译出不同跳转指令。

## 3.7 与指令集 / C 对照

- **第 4 章**：标志位是「隐式状态」，RISC-V 干脆放弃标志位、改用显式比较+分支；x86/ARM 保留条件码。这是 CISC vs RISC 的一个分水岭，第 4 章展开。
- **C**：`x += y` 可能是一条 `add`（直接改标志位），也可能被优化成 `lea`（不碰标志位）；`a < b` 对 `int`/`unsigned` 生成不同跳转——根子就在 3.6 的 CF/OF。
- **第 1 章主频**：ALU 加法器的关键路径直接决定 CPU 能跑多快——现代 CPU 用 CLA/树形进位把 64 位加法压进一个周期，才撑起 GHz 主频。

> 承上启下：**加法器是 ALU 的核心，串行进位是延迟、超前进位是加速；标志位把「运算结果的性质」编码成位，供分支指令消费。** 下一章把 ALU 装进指令系统，看一条指令如何指挥它运算。
