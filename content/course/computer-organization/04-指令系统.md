# 第 4 章 · 指令系统

**ISA（指令集架构）是软件与硬件的合同**（第 1.2 节）。本章讲这条合同怎么写的：一条指令的格式、操作数从哪里来（寻址方式），以及三大阵营 CISC（x86）/ RISC（ARM / RISC-V）的根本分歧。第 5 章会看到这些指令如何在数据通路上真正「跑」起来。

## 4.1 指令格式：操作码 + 地址码

一条指令 = **操作码（opcode）** + **地址码（操作数）**。按操作数个数分：

| 格式 | 形式 | 特点 |
|---|---|---|
| 三地址 | `add a, b, c` | a = b + c，直观但指令长 |
| 二地址 | `add a, b` | a = a + b，结果覆盖一个源（x86 主流） |
| 一地址 | `add a` | 隐含累加器 ACC（老式机器） |
| 零地址 | `add` | 隐含栈顶（JVM 字节码） |

**指令长度**是核心权衡：**定长**（RISC：RISC-V/ARM 都是 32 位）解码简单、利于流水线（第 6 章取指能一次取准）；**变长**（x86：1~15 字节）编码密度高、但解码器要逐字节判断边界，是流水线取指的负担。

## 4.2 寻址方式：操作数从哪来

操作数可以藏在六种地方，地址计算各有公式（记 `EA` 为有效地址）：

| 寻址方式 | 指令例子 | EA / 操作数 | 用途 |
|---|---|---|---|
| 立即 | `add r1, #5` | 操作数在指令里 | 常量 |
| 寄存器 | `add r1, r2` | 操作数在寄存器 | 最快，最常用 |
| 直接 | `ld r1, 0x1000` | EA = 0x1000 | 访问全局变量 |
| 寄存器间接 | `ld r1, (r2)` | EA = r2 | 指针解引用 |
| 变址 | `ld r1, 0x100(r2)` | EA = r2 + 0x100 | 数组 `a[i]`、结构体字段 |
| 基址+变址 | `ld r1, (r2, r3)` | EA = r2 + r3 | 二维数组 |
| 相对 | `jmp target` | EA = PC + 偏移 | 分支跳转 |

> 对比：这些寻址方式几乎一一对应 C 语言的结构——**寄存器间接 = 指针**、**变址 = `base + offset` 即 `a[i]` 或 `struct.field`**、**相对 = if/goto**。理解寻址方式，就是把第 10 章汇编、以及 C 指针课程里「`a[i]` 只是地址算术」这句落实成机器指令。

> 注意：RISC-V 只有 4 种寻址方式（立即/寄存器/寄存器间接/相对），x86 有十几种（含 `(%rbx,%rcx,8)` 这种「基址+变址×比例」）。寻址方式越多，单条指令越强大（CISC 的「一条 `mov` 干完取数+加+乘」），但解码越复杂、越难流水化——这是 CISC/RISC 分歧在寻址上的体现。

## 4.3 CISC vs RISC

两大设计哲学的对抗，根源在「把复杂度放软件还是硬件」：

| 维度 | CISC（x86） | RISC（ARM / RISC-V） |
|---|---|---|
| 指令长度 | 变长（1~15B） | 定长（32 位，ARM 有 16 位 Thumb） |
| 指令数量 | 数百上千 | 少而精（RISC-V 基础仅 ~40 条） |
| 寻址方式 | 十几种 | 3~4 种 |
| 访存 | `add` 可直接读写内存 | 只有 load/store 访存（load-store 架构） |
| 寄存器 | 少（x86-64 通用 16 个） | 多（RISC-V 32 个） |
| 实现 | 复杂解码器，常微码化 | 硬布线，易流水 |
| 代表 | 桌面/服务器 | 移动/嵌入式/新兴 |

**RISC 的核心信条**：让每条指令简单、等长、单周期，把复杂度交给编译器去安排——换来的是流水线好做（第 6 章）、主频高、功耗低。**CISC 的信条**：一条指令多做点事，减少指令数、省内存、省取指带宽，代价是解码难。

> 对比：历史结论是「RISC 赢得移动端，CISC 守住桌面/服务器」。x86 表面是 CISC，**现代 x86 CPU 内部却把复杂指令译码成 RISC 风格的微操作（µop）再执行**——等于在硬件里套了一层 RISC。而 ARM/RISC-V 靠定长指令吃满流水线红利。所以「CISC vs RISC」的边界早已模糊，真正决定性能的是微架构（第 5、6 章）。

## 4.4 x86 vs ARM vs RISC-V

| 特性 | x86-64 | ARM (AArch64) | RISC-V |
|---|---|---|---|
| 设计者 | Intel/AMD | Arm 公司（授权） | 开源社区 |
| 长度 | 变长 1~15B | 定长 32 位 | 定长 32 位（可扩展 16/48） |
| 寄存器 | 16 通用 + 标志位 | 31 通用 + 零寄存器 | 32 通用 + 零寄存器 x0 |
| 条件执行 | 标志位 + 条件跳转 | 部分条件执行（CSEL 等） | 无标志位，比较+分支 |
| 授权 | 封闭 | 需授权费 | 免费开源 |
| 生态 | 桌面/服务器霸主 | 手机/嵌入式 | 正在扩张 |

> 注意：RISC-V 的 `x0` 是**硬连线到 0 的零寄存器**——写它被丢弃、读它得 0。这消除了「清零要专门指令」，也让「寄存器间接寻址」（`ld a0, 0(x1)` 用 `x0` 作基址）天然变成「直接寻址」。ARM 的 `xzr` 同理。这是 RISC 用「约定俗成的特殊寄存器」替代「额外寻址方式」的典型手法。

## 4.5 与后续各章对照

- **第 5 章**：指令的每个字段（opcode、寄存器号、立即数）如何从指令寄存器 IR 被译码成控制信号——本章是「合同文本」，第 5 章是「执行合同的机器」。
- **第 6 章**：定长 vs 变长直接决定流水线取指难度；RISC 的 load-store 让「数据冒险」更规整、更易转发。
- **第 10 章**：本章的寻址方式、寄存器约定，落到 x86-64 汇编就是 `mov rax, [rbx+8]`、`lea rax, [rbx+rcx*4]` 这些具体语法。

> 承上启下：**ISA 决定「软件看到什么」，微架构决定「硬件怎么做」；CISC/RISC 是合同风格的两种写法，而寻址方式是合同里最灵活、也最见功力的一节。** 下一章把这份合同翻译成硬件，搭出数据通路。
