# 第 9 章 · 输入输出系统

CPU 和主存是「内部世界」，键盘、磁盘、网卡是「外部世界」。I/O 系统解决一件事：**让慢得多的外部设备，不把快 CPU 拖死**。三种交互方式——轮询、中断、DMA——本质是「谁来盯着设备」的分工。本章串起总线、外设接口、中断处理流程，也收束第 8 章缺页、以及操作系统设备管理（OS 第 7 章）的硬件半边。

## 9.1 三种 I/O 方式：轮询 vs 中断 vs DMA

| | 轮询 Polling | 中断 Interrupt | DMA |
|---|---|---|---|
| 谁主动 | CPU 反复查状态寄存器 | 设备就绪后「打断」CPU | DMA 控制器搬数据，CPU 只管起停 |
| CPU 代价 | 忙等，全程占用 | 只在响应时打断，可干别的 | 几乎不参与，最后收中断 |
| 延迟 | 取决于轮询频率 | 快，但有中断开销 | 搬完才通知 |
| 适用 | 设备极快、或极低频 | 事件驱动、通用 | 大批量块传输（磁盘/网卡） |

> 对比：三者的核心权衡是「**CPU 空转 vs 响应开销**」。轮询适合「设备永远瞬间就绪」（如某些高性能网卡，忙等比中断快，因为省了上下文切换）；中断适合「偶发事件」（按键、数据包到达），CPU 空闲时能执行别的进程；DMA 适合「成块搬运」（磁盘读写），把「从设备拷数据到内存」这件最累的活外包给 DMA 控制器，CPU 只需起停 + 收一个完成中断。

```text
轮询： CPU ──查状态──▶ 设备 …… CPU 空转等
中断： 设备 ──就绪，发中断──▶ CPU 打断当前任务去处理
DMA：  设备 ──DMA控制器──▶ 内存（数据直搬），完成后再中断 CPU
```

## 9.2 总线：地址 / 数据 / 控制

总线是 CPU、内存、外设之间的公共「信息高速公路」，分三类信号：

- **地址总线**：单向（CPU→设备），宽度决定可寻址范围（n 位可寻址 2ⁿ 个单元）。
- **数据总线**：双向，宽度决定一次传输多少位（总线带宽 = 数据宽度 × 频率）。
- **控制总线**：读/写、中断请求、总线请求、时钟等。

**总线仲裁**：多个设备抢总线（DMA 控制器、多个 CPU）时，由仲裁器按优先级/轮转决定谁能用——否则两个设备同时驱动总线会烧毁（总线冲突）。

> 注意：早期「单总线」所有设备共享，慢设备会拖慢快设备（木桶效应）；现代用**多级总线/点对点**（PCIe 是点对点串行，不再是共享总线），高速设备（显卡、SSD）走专属通道。**「总线」这个词在现代更像历史概念**——PCIe 用交换式点对点取代了真正的共享总线，但地址/数据/控制的抽象仍在。

## 9.3 外设接口：寄存器 + 编址

CPU 与外设交互的最小接口是**设备寄存器**（状态寄存器、数据寄存器、命令寄存器）。两种编址方式：

| 方式 | 做法 | 特点 |
|---|---|---|
| 端口映射 I/O | 独立 I/O 地址空间，专用 `in`/`out` 指令 | x86 传统 |
| 内存映射 I/O（MMIO） | 外设寄存器映射进内存地址空间，用普通访存指令 | RISC 主流，统一 |

> 对比：MMIO 把「访问外设」变成「读写某段内存地址」，好处是不需要专门指令、能用 Cache 机制（但外设寄存器通常要**禁用 Cache**——设备状态会自己变，缓存了反而读到旧值）。这正是第 7 章写策略里「MMIO 强制写直达」的原因。

## 9.4 中断处理流程

设备就绪 → 发中断请求（IRQ）→ CPU 在当前指令边界响应，完整流程：

```text
① 设备拉高中断请求线
② CPU 完成当前指令，检查是否有中断且未屏蔽
③ 关中断，保存现场（PC、寄存器压入内核栈）
④ 根据中断向量/原因，跳转到中断服务程序（ISR）
⑤ ISR 处理（读状态、取数据、清中断）
⑥ 恢复现场，开中断，返回被中断的程序
```

关键概念：

- **中断向量**：一张「中断号 → 服务程序入口」的表，硬件用中断号查表跳转（比逐个判断快）。
- **保存/恢复现场**：被中断程序不知道自己被打断，所以 PC、关键寄存器必须**原样恢复**——这是「中断透明性」的代价，本质和函数调用保存寄存器（第 10 章调用约定）同构，但发生在硬件/内核层。
- **关中断**：处理中断时屏蔽新中断，避免嵌套；或分级（优先级高的可抢占低的）。

> 对比：**中断 vs 异常 vs 系统调用**——三者都用同一套「打断 + 保存现场 + 向量跳转」机制，但来源不同：**中断**来自外部设备（异步），**异常**来自指令执行本身出错（同步：除零、缺页、段错误），**系统调用**是程序主动请求（`int 0x80`/`syscall` 指令）。第 8 章缺页就是「异常」的一种，OS 第 6/7 章大量依赖这三者。

## 9.5 与各章 / 操作系统衔接

- **第 8 章**：缺页 = 异常 → 中断服务 → 磁盘 DMA 读入 → 恢复进程，一条链把本章三种 I/O 方式全用上了（DMA 搬数据、中断通知完成、异常触发处理）。
- **第 5 章**：5.5 的「中断周期」就是本章流程里「CPU 在指令边界检查中断」的那一步，落在指令执行周期的固定位置。
- **OS 第 7 章（设备管理）**：本章讲「硬件怎么中断、怎么 DMA」，OS 讲「设备驱动怎么组织、中断怎么调度、I/O 调度算法（电梯算法）」——本章是它的硬件地基。
- **C/Java/Python**：所有语言的「读文件、收网络包」最终都落到 `read()`/`recv()` 系统调用，内核里走中断+DMA；Python 的 `asyncio`、Java NIO 的「非阻塞 I/O」，本质是**把轮询/中断的等待从「阻塞一个线程」改成「事件通知」**。

> 承上启下：**轮询是 CPU 主动盯、中断是设备主动喊、DMA 是搬数据外包；总线是三者共用的通道，中断向量表是「谁来处理」的路由。** 至此硬件拼图齐了，最后一章回到程序员视角——汇编与程序如何真正跑起来。
