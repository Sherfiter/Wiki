# 第 5 章 · CPU 结构与数据通路

第 4 章写了 ISA 这份合同，本章把它翻译成硬件：**数据通路（datapath）**是数据在其中流动的路，**控制器（controller）**是发号施令决定「每个周期数据往哪流」的指挥。先讲两种控制方式（硬布线 vs 微程序），再对比单周期与多周期两种实现，最后给出指令执行的标准周期划分。

## 5.1 寄存器组：可见 vs 不可见

CPU 内部寄存器分两类：

- **程序员可见（ISA 规定，第 4 章）**：通用寄存器（x86 的 rax/rbx…、RISC-V 的 x0~x31）、PC（程序计数器，指向下一条指令）、SP（栈指针）。
- **程序员不可见（微架构内部）**：
  - **IR**（指令寄存器）：锁存当前正在执行的指令。
  - **MAR**（存储器地址寄存器）：锁存要访问的内存地址。
  - **MDR**（存储器数据寄存器）：锁存与内存交换的数据（也叫 MBR）。

> 注意：MAR/MDR 不是「多此一举」——内存是异步的、慢的（第 7、8 章），CPU 不能边算边等。MAR/MDR 作为**边界锁存器**把「发出地址/数据」和「等待内存响应」拆成两个阶段，让 CPU 状态在时钟沿上稳定。这是时序电路设计的通用技巧：**跨异步边界的信号必须寄存**。

## 5.2 控制器：硬布线 vs 微程序

控制器把 IR 里的 opcode 翻译成一组控制信号（寄存器写使能、ALU 功能选择、存储器读写……）。两种实现：

| | 硬布线控制 | 微程序控制 |
|---|---|---|
| 原理 | 组合逻辑门直接由 opcode 算出控制信号 | 把每条指令对应一段「微指令」序列，存在控制存储器里 |
| 速度 | 快（一层门） | 慢（多查几次 ROM） |
| 可改 | 改指令要重设计电路 | 改微程序即可，灵活 |
| 复杂度 | 指令多则逻辑爆炸 | 规则、可扩展 |
| 典型 | RISC（RISC-V/ARM） | 早期 CISC（x86 复杂指令） |

> 对比：硬布线 = 「为每条指令焊死专用逻辑」，微程序 = 「用一个小型只读程序来解释指令」。微程序控制器本质是「**在 CPU 里又套了一层解释器**」——这和第 1 章层次结构里「用软件解释硬件」的思想同构。现代 CPU 折中：简单指令硬布线快跑，复杂指令（x86 的 `rep movsb`、复杂寻址）走微码。

## 5.3 数据通路：数据怎么流

一条 `add r1, r2, r3`（r1 = r2 + r3）在一个周期内的数据流：

```text
PC ──▶ 取指令 ──▶ IR（指令寄存器）
                     │
        r2 ──▶ ┐     │  opcode 译码
        r3 ──▶ ┼──▶ ALU ──▶ r1（写回）
                │
              控制信号（选通各数据源/目的地）
```

数据通路的每个节点（寄存器、ALU、多路选择器、存储器）之间用**总线或专用连线**连接，控制信号像扳道岔一样决定数据走哪条路。设计数据通路的两个关键：**多路选择器（MUX）** 在多个数据源里选一个进 ALU；**寄存器文件**支持同时读两个、写一个（一个周期内 `rd = rs1 op rs2`）。

## 5.4 单周期 vs 多周期

一条指令在**一个时钟周期**内完成 = 单周期；拆成**多个周期** = 多周期。这是第 6 章流水线的直接前身。

| | 单周期 | 多周期 |
|---|---|---|
| 周期数/指令 | 1 | 若干（取指/译码/执行/访存…） |
| 时钟周期长度 | 由**最慢指令**决定（load 要访存+ALU） | 由**最慢的阶段**决定，周期可更短 |
| 功能部件 | 每条指令独占整个通路 | 不同阶段复用同一部件（ALU 被取指、执行共用） |
| 性能 | 简单，但浪费——快指令也要等慢指令 | CPI 大但周期短，净收益通常更好 |
| 硬件 | 部件不能复用，冗余 | 部件复用，省面积 |

> 注意：单周期的死穴是「**木桶效应**」——时钟周期必须容纳最长的 load 指令（取指 + 读寄存器 + 访存 + 写回），导致所有指令都按最慢的节奏跑，快指令（纯算术）的大量时间被空等。多周期把长指令拆开，让周期变短，但每条指令的 CPI 变大。**流水线（第 6 章）才是两全其美的解：周期短 + 吞吐 1 IPC。**

## 5.5 指令执行周期

从取指到完成，一条指令的标准生命周期（多周期机的划分，也是流水线的五级雏形）：

```text
① 取指周期   MAR←PC，读内存，IR←MDR，PC←PC+1（顺序）
② 间址周期   若寻址方式需要，再访存取操作数地址
③ 执行周期   操作数进 ALU 运算
④ 中断周期   若检测到中断请求，保存现场、转中断服务（第 9 章）
```

只有访存指令（load/store）才需要完整的「访存」步骤，这解释了为什么单周期按 load 定周期是浪费。

> 对比：这几个周期和 C 语言执行过程一一对应——`PC←PC+1` 是「顺序执行」，`call/jmp` 会改写 PC 打破顺序（第 10 章调用约定）；「间址周期」就是 C 指针课程的**二级指针/间接寻址**在硬件上的动作；「中断周期」是第 9 章中断处理的前半段。CPU 的「取指-执行」循环，是程序运行的最小节拍。

## 5.6 与后续各章对照

- **第 6 章**：把 5.5 的周期拆成五级、各自配一个独立硬件段，让五条指令同时处于不同阶段——流水线是数据通路「部件专用化 + 锁存器分段」的产物。
- **第 3 章**：ALU 是数据通路的核心部件，它的关键路径（第 3.2 节加法器）直接决定单周期机的时钟周期长度。
- **第 10 章**：PC、IR、寄存器文件、MAR/MDR 这些抽象部件，在汇编层面表现为「下一条指令」「当前指令」「寄存器」——写汇编时脑子里就是这张数据通路图。

> 承上启下：**控制器决定「做什么」，数据通路提供「走哪条路」；单周期傻快但浪费，多周期省但慢，流水线（第 6 章）用分段复用同时拿到「周期短」和「吞吐高」。**
