# 第 1 章 · 操作系统概述

操作系统（OS）是夹在硬件与应用之间的**资源管理者**与**服务提供者**：向下管理 CPU、内存、磁盘、外设，向上为程序提供统一的抽象接口。

## 1.1 功能与目标

四个核心功能，各有目标：

| 功能 | 管理对象 | 目标 |
|---|---|---|
| 处理机管理 | CPU | 提高 CPU 利用率、多道并发 |
| 存储器管理 | 内存 | 隔离、扩充（虚拟内存）、分配回收 |
| 文件管理 | 磁盘 | 按名存取、安全共享 |
| 设备管理 | I/O 设备 | 屏蔽硬件差异、缓冲与调度 |

两个根本目标：**方便用户**（隐藏硬件细节，提供抽象）与**提高资源利用率**（多道程序、并发）。

## 1.2 系统调用：用户态 vs 内核态

CPU 至少提供两种特权级别：**用户态（user mode）**与**内核态（kernel mode）**。

- 用户态：只能执行非特权指令、访问自己的地址空间。
- 内核态：可执行特权指令（关中断、改页表、直接访问 I/O）、访问任意内存。

```
用户态程序
    │  write(1, "hi", 3)     ← 发起系统调用
    ▼
陷入 (int 0x80 / syscall)     ← 硬件切换到内核态
    ▼
内核态：查系统调用表 → 执行内核函数 → 恢复现场
    ▼
返回用户态，继续执行下一条指令
```

进入内核态的三种方式：**系统调用**（主动、同步）、**异常**（除零、缺页，被动）、**中断**（外设信号，异步，见第 9 章）。三者殊途同归——都要保存现场、切内核栈、执行内核代码、恢复返回。

```c
write(1, "hi\n", 3);   // 一次系统调用：用户态 → 内核态 → 用户态
```

> 对比：**用户态 vs 内核态**。二者是「权限」而非「角色」：同一进程时而用户态、时而内核态。用户态执行普通代码，内核态执行系统调用/中断处理。切换代价（保存/恢复现场、切换栈、可能刷 TLB）远大于一次普通函数调用，所以系统调用要「批量」用——`read` 一次读一大块，而非逐字节读。

## 1.3 内核结构：宏内核 vs 微内核

| | 宏内核（Monolithic） | 微内核（Microkernel） |
|---|---|---|
| 代表 | Linux、Unix、Windows(混合) | Minix、QNX、Mach |
| 内核态包含 | 进程/内存/文件/驱动等全部 | 仅 IPC、调度、基础内存 |
| 服务方式 | 直接函数调用 | 消息传递（IPC） |
| 性能 | 快（无消息开销） | 慢（IPC 开销大） |
| 可靠性 | 一个驱动崩溃可能拖垮内核 | 服务隔离，崩溃可重启 |
| 扩展性 | 编译进内核/模块 | 服务独立加载 |

> 对比：宏内核把尽可能多的功能放进内核态，换**性能**；微内核把功能推到用户态服务进程，换**可靠性/可维护性**，代价是频繁的 IPC 通信。现代 Linux 是宏内核 + 可加载模块（LKM）的折中，Windows 是「混合内核」——两者都向中间靠拢。

> 承上启下：本章确立「内核态 vs 用户态」「宏内核 vs 微内核」两对坐标，第 2 章进入内核管理的第一个对象——进程。系统调用的「陷入机制」会在第 9 章「中断」处回扣（陷入本质是一种软中断）；`write`/`malloc` 这些系统调用，正是 C 程序（第 10 章）背后真正发生的事。
