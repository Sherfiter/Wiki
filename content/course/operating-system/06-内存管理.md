# 第 6 章 · 内存管理

内存管理的核心问题：**把有限的物理内存，安全、高效地分给多个进程**，并用虚拟内存让每个进程以为独占全部空间。

## 6.1 连续分配

把内存分成连续块分给进程。三种**动态分区**放置策略：

- **首次适应（First Fit）**：从头找第一个够大的空闲块。快，但低地址端碎片多。
- **最佳适应（Best Fit）**：找最接近大小的空闲块。浪费最小，但产生大量极小碎片，且要排序/遍历。
- **最坏适应（Worst Fit）**：找最大的空闲块。剩余块仍较大可用，但大块很快耗尽。

连续分配产生**外部碎片**：总空闲够，但都太小且不连续，装不下新进程。解决：**紧凑（compaction）**，代价高。

## 6.2 分页 vs 分段

> 对比：**分页（paging）vs 分段（segmentation）**。

| | 分页 | 分段 |
|---|---|---|
| 划分依据 | 固定大小（如 4KB），无逻辑意义 | 逻辑单元（代码/数据/栈），变长 |
| 用户可见 | 不可见 | 可见，符合程序员视角 |
| 地址空间 | 一维（页号+页内偏移） | 二维（段号+段内偏移） |
| 碎片 | 内部碎片（最后一页浪费） | 外部碎片（段间空隙） |
| 共享/保护 | 按页，粒度粗 | 按段，语义清晰 |
| 现代用法 | 主流（x86 分页） | 常与分页结合（段页式） |

分段符合程序结构（代码段只读、栈段可长），但外部碎片难处理；分页无外部碎片但破坏逻辑边界，故现代系统用**段页式**：先分段再分页，兼顾二者。

## 6.3 虚拟内存

**虚拟内存**：把外存（磁盘）当作内存的延伸，进程只把**当前需要的页**调入内存，其余留在磁盘（交换区）。

- **局部性原理**：时间局部性（刚用过的可能再用）+ 空间局部性（附近的可能用）。这是虚拟内存能成立的根基。
- **缺页（page fault）**：访问的页不在内存，触发缺页中断，从磁盘调入。缺页是第 7 章置换算法的触发器。

好处：进程地址空间可大于物理内存、隔离保护、共享库。代价：缺页时磁盘访问慢（毫秒级 vs 内存纳秒级）。

## 6.4 地址转换：页表 + 快表

逻辑地址 → 物理地址分两步：

$$\text{物理地址}=\text{页框号}\times\text{页大小}+\text{页内偏移}$$

```c
// 页表项存：页框号 + 有效位 + 权限位
phys = page_table[vpn].frame * PAGE_SIZE + offset;
```

- **页表**：每个进程一张，存在内存。页号索引 → 页框号。多级页表解决「页表本身太大」。
- **TLB（快表，Translation Lookaside Buffer）**：CPU 里的高速缓存，缓存最近用过的页表项。命中则省一次内存访问（页表读）。
- **有效访问时间**：TLB 命中 ≈ 1 次内存访问；未命中 ≈ 2 次（先查页表再访存）。TLB 命中率是性能命门。

> 对比：**内部碎片 vs 外部碎片**。内部碎片：分给进程但进程用不完的「块内」浪费（分页最后一页）；外部碎片：块与块之间无法利用的「空隙」（连续分配/分段）。分页只有内部碎片、无外部碎片；分段/连续分配只有外部碎片。二者此消彼长，无法同时为零。

> 承上启下：虚拟内存的「缺页」是第 7 章置换算法的入口；TLB 命中率是第 2 章「上下文切换开销」被放大的地方（换进程可能刷 TLB）。分页的「页表 + 页框」在第 8 章文件系统里有个孪生概念——inode 与数据块。内存布局的「段」正是 C 指针课程第 2 章的五大段（第 10 章闭环回扣）。
