# 第 10 章 · OS 实例与闭环

本章把前九章的抽象落到两个真实系统上，并用 Linux 实操串起「进程 → 内存 → 文件」全链路，最后回扣 C 指针课程的内存布局，形成闭环。

## 10.1 Linux vs Windows 结构对比

> 对比：**Linux vs Windows**。

| | Linux | Windows |
|---|---|---|
| 内核类型 | 宏内核 + 模块（LKM） | 混合内核（NT） |
| 可执行格式 | ELF | PE |
| 文件系统 | ext4/xfs/btrfs | NTFS/ReFS |
| 权限模型 | POSIX（uid/gid/rwx） | ACL/SID |
| 一切皆文件 | 是（/proc、/dev） | 部分（对象管理器） |
| 线程/进程 | 轻量进程（clone） | 线程为主 |
| 源码 | 开放（GPL） | 闭源 |

共同点：都支持虚拟内存、多线程、日志文件系统、抢占式多任务；差异主要在**内核组织、权限模型、文件抽象**三处。

## 10.2 Linux 进程 / 文件命令实操

```bash
ps aux              # 查看进程（PID、状态、内存 RSS）
top                 # 实时查看 CPU/内存/进程
kill -9 1234        # 发 SIGKILL 信号终止进程
cat /proc/1234/maps # 查看进程的内存映射（五大段）
free -h             # 物理内存/交换区
df -h; du -sh dir   # 磁盘占用
ls -li              # -i 显示 inode 号
```

- `ps` 的 `STAT` 列直接对应第 2 章进程状态：`R`（运行）、`S`（等待）、`Z`（僵尸）、`T`（停止）。
- `/proc/<pid>/maps` 能亲眼看到第 6 章说的各段与映射区。

## 10.3 进程内存布局：回扣 C 指针课程

C 指针课程第 2 章画过「进程五大段」——**它就是本章第 6 章内存管理的用户态视图**。用一段代码把两门课钉在一起：

```c
#include <stdio.h>
#include <stdlib.h>
int  g = 1;               // Data 段
char *lit = "hello";      // lit 在栈，"hello" 在 .rodata
void f(void) {
    int local = 2;        // 栈帧局部变量 [rbp-offset]
    int *p = malloc(8);   // 堆
    printf("%p %p %p %p\n", &g, lit, &local, p);
}
```

- `&g`（Data）、`lit`（.rodata）、`&local`（栈）、`p`（堆）四个地址分属四段——用 `cat /proc/self/maps` 或直接看地址大小关系即可验证。
- 第 2 章（C 指针）讲的**栈帧、悬空指针、栈溢出**，在 OS 视角就是第 6 章「栈段向下生长 + 缺页/越界触发 SIGSEGV」；`malloc` 的堆正是 OS 用 `brk`/`mmap` 系统调用（第 1 章）从内核要来的。

> 闭环：**C 指针的「进程内存布局」 = 操作系统的「虚拟内存 + 分段」的用户态投影。** 指针课程让你「看清内存」，OS 课程让你「看懂谁在管内存」——两门课在此合流。

> 承上启下：本课程到此闭环：第 1 章系统调用是 C 里每个 `write`/`malloc` 的底层；第 2–5 章的进程/调度/同步/死锁回答了「CPU 如何并发」；第 6–7 章回答了「内存如何虚拟」；第 8–9 章回答了「数据如何落盘」；本章把这一切绑在 Linux/Windows 两个实例上，并接回 C 指针的内存布局。操作系统不再是黑盒，而是一张能逐层拆解的图。
