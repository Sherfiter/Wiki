# 第 4 章 · 进程同步

多个线程并发访问共享数据会产生**竞态（race condition）**：结果取决于执行顺序。同步就是约束这种并发。

## 4.1 临界区

**临界区（critical section）**：访问共享资源的代码段。必须满足：

1. **互斥**：任一时刻至多一个进程在临界区。
2. **前进**：临界区空闲时，想进去的进程能尽快进（不能空等）。
3. **有限等待**：请求者等待时间有上界（不能饿死）。

实现演进：**软件法**（Peterson 算法，现代 CPU 乱序下已不可靠）→ **硬件法**（关中断、`TestAndSet`/`Swap` 原子指令）→ **信号量/锁**（封装硬件原语）。

## 4.2 信号量 PV 操作

信号量（semaphore）是一个整型变量 + 原子操作：

- **P（wait，荷兰语 Proberen）**：`s--`，若结果 < 0 则阻塞自己。
- **V（signal，Verhogen）**：`s++`，若结果 ≤ 0 则唤醒一个等待者。

```c
sem_t mutex = 1;          // 互斥信号量，初值 1
P(&mutex);                // 进入临界区前
/* 临界区 */
V(&mutex);                // 离开临界区后
```

初值为 1 的信号量就是**互斥锁**；初值为 N（>1）的用于**计数/资源管理**（如 N 个空缓冲区）。

## 4.3 经典同步问题

- **生产者-消费者**：满则生产者停，空则消费者停。用 `empty`（初值 N）与 `full`（初值 0）两个信号量 + 一个互斥 `mutex`。P 操作的**顺序很关键**：先 P(empty) 再 P(mutex)，否则死锁。
- **读者-写者**：多读可并发，写者独占。读者优先/写者优先/公平三种策略。读者优先可能饿死写者。
- **哲学家就餐**：5 个哲学家围桌，每人左右各一支筷子，需同时拿两支配才能吃。直接「先拿左再拿右」会死锁；解法：奇数先左、偶数先右，或限制最多 4 人同时拿筷。

生产者-消费者的典型实现（注意 P 顺序）：

```c
// 生产者：先 P(empty) 再 P(mutex)，顺序不能反
P(&empty); P(&mutex);
put_item();
V(&mutex); V(&full);

// 消费者：先 P(full) 再 P(mutex)
P(&full); P(&mutex);
get_item();
V(&mutex); V(&empty);
```

## 4.4 互斥锁 vs 信号量

> 对比：**互斥锁 vs 信号量**。

| | 互斥锁（mutex） | 信号量（semaphore） |
|---|---|---|
| 本质 | 二元信号量 | 计数信号量 |
| 用途 | 仅互斥 | 互斥 + 资源计数 + 同步顺序 |
| 所有权 | 谁加锁谁解锁（有 owner） | 无所有权，任意线程可 V |
| 递归 | 不可递归加锁 | 可多次 P |
| 优先级 | 有优先级继承防优先级反转 | 通常无 |

> 对比：**忙等待 vs 阻塞**。忙等待（自旋锁 spinlock）——P 失败后循环检测 `while (flag);`，不放弃 CPU；阻塞——P 失败把自己挂起，让出 CPU。自旋锁**不切换上下文**，适合临界区极短（几条指令）的场景；阻塞适合临界区长（如 I/O）的场景，代价是一次上下文切换。

> 承上启下：本章的「竞态」直接源于第 2 章「线程共享内存」；信号量的 PV 与第 5 章死锁的四个条件环环相扣（P 顺序错就会构成循环等待）；「忙等待 vs 阻塞」在 Linux 源码里就是 spinlock vs mutex（第 10 章）。
