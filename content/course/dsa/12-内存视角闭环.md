# 第 12 章 · 内存视角闭环

前面学了 11 章结构与算法，这一章回到最底层：**每个结构在栈/堆上到底长什么样？指针怎么把它们串起来？** 这里与 C 指针课程第 1 章（指针与内存模型）、第 2 章（栈帧与内存布局）、第 9 章（动态内存）直接呼应，形成闭环。

## 12.1 顺序表：一段连续堆内存

```c
typedef struct { int *data; int len, cap; } SeqList;
```

`SeqList` 本身若定义在函数里是**栈**上的结构体（约 12 字节），但它的 `data` 指向 `malloc` 来的**堆**块。`a[i]` 编译成 `*(data + i)`——基址 + 偏移，一次地址计算 + 一次解引用（C 指针第 4 章）。

```
栈                   堆
┌────────────┐       ┌──────────────────────┐
│ data ──────┼──────►│ 0 │ 1 │ 2 │ ... │n-1│  ← 连续 int
│ len  cap   │       └──────────────────────┘
└────────────┘
```

## 12.2 链表：节点离散在堆，靠 next 串联

```c
typedef struct Node { int val; struct Node *next; } Node;
```

每个 `Node` 各自 `malloc`，地址无规律地散布在堆里，`next` 存下一个节点的地址。

```
栈        堆
┌──────┐  ┌──────┬───┐   ┌──────┬───┐   ┌──────┬────┐
│ head─┼─►│ val1 │ ──┼──►│ val2 │ ──┼──►│ val3 │NULL│
└──────┘  └──────┴───┘   └──────┴───┘   └──────┴────┘
          地址A            地址B(≠A+16)   地址C
```

`head->next->val` 是两次解引用：先顺着 `next` 拿到 B，再读 B 的 `val`。**树、图、跳表、Trie 都是这个模型的推广**——多几个指针字段而已（第 5、6、11 章）。

## 12.3 栈 vs 堆：生命周期决定结构选型

| 内存 | 分配方式 | 生命周期 | 适合放 |
|---|---|---|---|
| 栈 | 编译器自动 | 函数返回即失效 | 局部变量、小数组 |
| 堆 | malloc/free | 手动控制 | 链表节点、树节点、动态数组 |

关键推论（C 指针第 2 章）：**链表的节点必须放堆**——因为节点要在函数返回后继续存在。放栈上的局部节点一旦函数返回就悬空。这也是为什么「返回局部变量地址」是经典陷阱。

## 12.4 缓存局部性：数组快、链表慢的本质

CPU 从内存读数据以**缓存行（cache line，64 字节）**为单位。顺序表元素连续，读 `a[i]` 时把邻居一起搬进缓存，下次访问 `a[i+1]` 命中；链表节点离散，每次跳 `next` 大概率缓存未命中（cache miss），要重新访内存，慢一个数量级。

```c
// 同样遍历 n 个元素：数组远快于链表（缓存局部性）
for (int i = 0; i < n; i++) sum += arr[i];          // 顺序访问，缓存命中率高
for (Node *p = head; p; p = p->next) sum += p->val; // 随机跳转，频繁 miss
```

## 12.5 各结构内存开销

| 结构 | 每元素额外开销 | 来源 |
|---|---|---|
| 顺序表 | 0（或预留 cap 浪费） | 纯数据 |
| 单链表 | 8 字节 | 一个 next 指针 |
| 双向链表 | 16 字节 | prev + next |
| 二叉树 | 16 字节 | left + right |
| 哈希表（链地址） | 桶数组 + 节点指针 | 桶 + next |
| Trie | 每字符一个指针数组 | 26 或 256 个指针 |
| 跳表 | 多层 next 指针 | 期望 2×指针 |

```c
printf("%zu %zu\n", sizeof(int), sizeof(Node));  // 8 vs 16：一个指针就翻倍
```

> 对比：数组 vs 链表缓存局部性——数组内存连续、顺序访问命中缓存、还有硬件预取；链表节点离散、指针跳转打破局部性。**这解释了为什么「理论上」链表插入 O(1) 快，实际大量数据下数组的遍历和排序常常反超**：常数因子藏在缓存里。

> 对比：各结构内存开销——顺序表几乎零额外开销但需连续大块；链表/树每个节点付指针税换灵活性；Trie、跳表用更多指针换查找速度，是「空间换时间」在内存布局上的具象（第 1 章）。

## 12.6 闭环：从复杂度回到内存

第 1 章的复杂度只数「操作次数」，本章补上「每次操作的常数代价」：一次 `*p` 解引用、一次缓存 miss、一次 malloc 都是真实时间。**数据结构 = 内存布局 + 指针关系 + 操作算法**，三者统一后，前面 11 章的所有选择才有了物理依据。

> 承上启下：这是本课程的终点，也是 C 指针课程的续集——指针第 1 章给「地址/解引用」的抽象，第 2 章给「栈帧/堆」的布局，第 9 章给 malloc/free 的细节，本课程用 12 章把这三件武器锻造成「用 C 设计数据结构」的完整能力。此后任何新结构，你都能在脑子里画出它的内存图。
