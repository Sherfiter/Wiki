# 第 1 章 · 指针与内存模型

指针是 C 的灵魂。要真正理解指针，必须先理解**内存到底长什么样**——很多人卡在指针上，不是语法不会，而是脑子里没有内存模型。

## 1.1 内存是字节数组，地址是下标

把进程的地址空间想象成一条巨大的**字节数组**，每个字节都有一个唯一的编号，这个编号就是**地址（address）**。指针就是存「地址」的变量——它本身也是一个对象，占自己的字节，存的内容是别人的地址。

```
地址     内容
0x1000   ┌──────────┐
0x1001   │          │   每个格子 1 字节
0x1002   │          │
...      │          │
0x1008   │  42      │  ← 变量 x 占 4 字节，首地址 0x1008
0x100C   │  ...     │
```

```c
int  x  = 42;      // x 是 int，占 sizeof(int) 字节
int *p  = &x;      // &x 取 x 的首地址，存进 p
printf("%p\n", (void*)p);   // 打印地址，如 0x7ffc...
printf("%p\n", (void*)&x);  // 与 p 相同
```

- `&x` 是「取地址」，`*p` 是「解引用」（顺着 p 里的地址去读写那个位置）。
- `*p = 10;` 等价于直接改 `x`，因为 `*p` 和 `x` 是**同一块内存**的两个名字。

## 1.2 指针类型决定「读几个字节、怎么解释」

指针不只是「地址」，还带**类型**。类型信息告诉编译器两件事：

1. 解引用时**读/写多少字节**（`int*` 读 `sizeof(int)` 字节，`char*` 读 1 字节）；
2. 这些字节**按什么方式解释**（有符号？浮点？）。

```c
int x = 0x41424344;          // 小端机上内存字节是 44 43 42 41
char *c = (char*)&x;         // 强制按字节看
printf("%c\n", c[0]);        // 'D'（小端：最低字节在前）
```

同一块内存，用 `int*` 看是整数，用 `char*` 看是一串字节——**位模式没变，解释方式变了**。这是「类型系统」在 C 里的本质：类型是对同一段位模式的解读约定。

## 1.3 指针本身也是对象，有大小和对齐

```c
printf("%zu %zu %zu\n", sizeof(int*), sizeof(char*), sizeof(void*));
```

在 64 位平台上，三种指针通常都是 **8 字节**——因为要能容纳 64 位地址。指针大小跟它指向的类型大小**无关**（`char*` 和 `int*` 一样大）。

但指针的**对齐（alignment）**是硬约束：一个 `int*` 通常要求 4 或 8 字节对齐，即地址必须是 `_Alignof(int)` 的整数倍。把一个不对齐的地址强转成 `int*` 再解引用，在很多架构上会直接崩（SIGBUS），至少也是未定义行为。

```c
#include <stdalign.h>
printf("%zu\n", alignof(int));    // 通常 4
printf("%zu\n", alignof(double)); // 通常 8
```

## 1.4 空指针：NULL 与 nullptr

指针不指向任何合法对象时，应赋值为**空指针（null pointer）**。空指针是一个明确的「无效」值，不等于「未初始化」——未初始化是垃圾值，比空指针危险得多。

```c
int *p = NULL;        // C 传统写法（NULL 是宏，通常 ((void*)0)）
int *q = nullptr;     // C23 起引入的真正的关键字，类型是 nullptr_t
if (p == NULL) { /* 未初始化/未分配 */ }
```

- 解引用空指针是**未定义行为**，现代 OS 会触发段错误（SIGSEGV）——这是好事，越早崩越早知道。
- 判断指针是否有效，标准做法是 `if (p)` 或 `if (p != NULL)`，但**这不保证它指向的地址一定合法**，只能排除空指针这一种情况。

## 1.5 通用指针 void*

`void*` 是「万能指针」：任何对象指针都能隐式转成 `void*`，用于**只搬运地址、不关心类型**的场景（如 `malloc` 返回、回调传参）。

```c
void *mem = malloc(64);     // malloc 返回 void*，不关心你要存什么
int  *arr = mem;            // C 中 void* 隐式转 int* 合法（C++ 需要强转）
```

- `void*` **不能直接解引用**（编译器不知道读几字节），也不能做算术（见第 3 章）。
- `void*` 保证能存下任何**对象指针**，但不保证能存**函数指针**（POSIX 保证，C 标准不保证）。

## 1.6 与汇编 / 其他语言对照

- **汇编**：指针就是「间接寻址」。`*p = 10` 编译成 `mov [reg], 10` 之类——寄存器里放地址，方括号表示「去这个地址」。C 的 `*` 就是汇编的间接寻址，`&` 是 `lea`（取有效地址）。
- **Java**：没有裸指针，对象引用（reference）由 JVM 管理，地址不可见、不可运算、有 GC 兜底；换来的是**安全**，丢掉的是「直接摸内存」的能力和零开销。
- **C++**：指针与 C 完全一致，另加了**引用**（语法糖，本质是指针但不可为空、不可改绑）和**智能指针**（RAII 自动管理生命周期）。
- **Python**：一切皆对象，变量名只是「名字到对象」的绑定，地址被解释器彻底藏起来，`id()` 只是近似。

> 核心心智模型：**指针 = 存地址的变量；类型 = 对地址处字节的解释方式；解引用 = 按类型去读写那块内存。** 把这三句话刻进脑子，后面所有章节都是它们的推论。
